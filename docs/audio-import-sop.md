# 章节现场音频导入 SOP

更新：2026-11-13。默认策略已由用户确认：**轻度降噪，优先保全人声**。

本流程用于目前由操作者整理的章节讲解音频，不改变普通用户上传的 10 分钟 / 20 MB 限制。当前环境为项目本地 PGlite 和本地媒体目录；外部环境须单独明确资源和发布范围。

## 处理顺序

1. 保存原始整场录音和来源关联，核对所选章节与讲解起止时间。
2. 从来源裁出用户选择公开的讲解片段，排除开场、后续讨论等未选择的内容。保存这份未降噪片段作为恢复依据。优先从原始录音仅编码一次；已有 MP3 允许生成一个降噪副本，不重复处理上一代降噪输出。
3. **自动轻度降噪**：调用 `prepareDenoisedAudio()`，产出独立 MP3 和处理清单；不覆盖输入，不上传第三方服务。
4. **自动校验**：完整解码、时长、声道、采样率、电平、峰值、文件大小及来源哈希一致性。失败即停止导入，现有公开音频维持原状态；不静默用原件冒充降噪结果。
5. 导入通过校验的独立版本。媒体对象键包含处理版本和结果哈希。数据库事务中关联新媒体、隐藏旧音频并记录旧媒体 ID、输入/输出哈希及处理参数；同一处理结果重复执行不新增播放器，不自动恢复曾被隐藏的版本。
6. 核验分享详情只返回一份可播放音频，普通读取为 200、Range 为 206；媒体隐藏后的普通读取与 Range 均应拒绝。仍由站内媒体接口鉴权，不发布存储直链。

## 可运行入口

需要可信来源安装的 FFmpeg，包含 `afftdn`、`highpass`、`astats` 和 `libmp3lame`。默认从 PATH 读取，也可设置 `FFMPEG_PATH` 为本机可执行文件绝对路径。当前机器使用已有的 `/private/tmp/ddj-audio-tools/imageio_ffmpeg/binaries/ffmpeg-macos-aarch64-v9.0`，此临时路径不是长期依赖；换机器后应重新配置。

单独准备一条音频，不打开数据库：

```sh
FFMPEG_PATH=/path/to/ffmpeg npm run audio:denoise -- \
  .local/imports/audio/clips/chapter-9-lecture.mp3
```

默认产物为 `.local/imports/audio/denoised/<任务哈希>/denoised.mp3` 和 `manifest.json`，均不进入公开 DTO。任务哈希来自输入内容、固定处理参数与 FFmpeg 版本；重复执行复用校验通过的结果，并重新核验输出哈希。处理中使用独占任务锁；遇到锁冲突即退出，不重复编码。进程被强制终止时，先核对原进程确已停止，再人工清理对应锁，不能删锁抢跑。

当前四章的一次性导入入口是 `.local/imports/attach-lecture-audio.ts`，已接入上述函数；先全部完成处理，再打开数据库。**执行数据库导入前必须停止占用本地 PGlite 的开发服务**。执行该脚本会替换本地公开播放器版本，因此只准备候选音频时使用上方命令。以后新增章节沿用同一准备函数，不另抄滤镜命令。

## 固定处理配置与门禁

- 处理版本：`speech-gentle-v1`。
- 滤镜：`highpass=f=60,afftdn=nr=6:nf=-50:tn=1:gs=8`。60 Hz 高通加 6 dB 轻度频谱降噪，跟踪底噪并平滑增益。参数依据 [FFmpeg 官方滤镜说明](https://ffmpeg.org/ffmpeg-filters.html#afftdn)。6 dB 是参数上限设置，不是每份音频实测降低了 6 dB。
- 输出沿用原采样率、声道数，MP3 32 kbps，与现有四条单声道讲解音频的编码规格一致；清除来源元数据。不加噪声门，不裁静音，不变速，不做自动大幅增益补偿。
- 输入/输出时长差不超过 0.25 秒，完整解码无错误，声道和采样率保持一致。
- RMS 电平不能低于 -65 dB，下降不超过 6 dB、上升不超过 1 dB；输出峰值低于 0 dB，文件不超过 20 MB。输出过长不自动截短；异常不自动提高压制强度。
- 这些是技术异常门禁，**不能证明逐字人声无损、清晰度提高或降噪听感合格**。对突然的人声串扰、椅子拖动、音乐和混响效果有限，不能当成说话人分离。

轻声、远处发言或诵读内容容易受损，因此保留原音频和可回退版本；首次使用新处理版本时，对照试听开头、中段、末尾及轻声处。发现吞字、金属音或抽吸声时保留原版，另行调整处理版本，不就地覆盖固定参数或原文件。

## 失败与恢复

- 缺工具、处理失败、超时、来源文件改变、质量门禁失败：非零退出，不写入新的公开媒体。
- 处理成功而数据库写入失败：保留候选文件和清单；修复后复用同一结果，重复导入不产生新版本。对象先落盘、事务再关联，失败留下的未关联对象不视为已发布。
- 发布后需回退：用审计中的 `previousMediaIds` 核对对应分享及当前显隐状态，在同一事务中隐藏新版本、恢复明确选择的旧版本并记回退审计。不要恢复已经撤回的整条分享或无关媒体。原存储对象保持不变。
