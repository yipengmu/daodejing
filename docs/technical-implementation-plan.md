# 《道德经》公益共读平台：技术编码计划书

- 状态：实施准备稿 v0.1
- 日期：2026-10-31
- 依据：[Proposal Spec](./proposal-spec.md)、[页面流程 Spec](./product-page-flow-spec.md)、[技术架构 Spec](./technical-architecture-spec.md)、[设计指导 Spec](./design-guidelines-spec.md)
- 范围：MVP 技术工作拆分、交付顺序、依赖和验收口径；不包含代码实现

## 1. 编码目标

交付一个移动优先、适配桌面端的响应式 Web MVP，跑通匿名阅读与发现、账号注册登录、章节分享、共读记录、道场资料及定位发现闭环。

编码前核对并沿用家谱项目已验证的 Node.js、React、Vercel、Prisma、认证和媒体技术实现方式；为道德经项目建立独立 Neon 数据库、独立环境密钥和独立媒体资源。认证与媒体代码/方案可以复用，服务实例与业务数据不共享。

本计划不包含面向用户的 AI、Agent Harness 工程自动化、运营管理后台、人员标记界面、话题讨论/评论、推荐算法、次数看板、活动合并、产品内路线预计用时或完整导航。

## 2. MVP 范围和关键约束

### 包含

- 匿名浏览王弼本 1—81 章原文、来源信息和公开分享。
- 手机号或邮箱注册与登录；手机号注册不要求提供邮箱。个人资料页可选绑定并验证找回邮箱。
- 对外公开 profile 字段（如用户展示名）默认公开；手机号、登录邮箱、验证码等认证/找回信息始终私有，不从公开内容 API 返回。
- 登录用户发布章节分享、提交共读记录、创建/维护本人道场资料、隐藏自己的分享。
- 按章节、城市、道场发现公开内容和道场；附近发现及临时地点录入必须授权设备定位。
- 以服务端提交时间（分钟级）记录每次提交；每个章节分别提交，每次登录用户提交均增加一条原始记录，不做去重。
- 用户隐藏内容后立即从公开读取接口排除；逻辑删除后保留必要 tombstone/关联，不再公开提供，也不得进入未来 AI 检索。
- 文字分享及可选图片、音频、视频原始文件上传；媒体大小/时长/格式限制在 Phase 0 按独立存储方案定值。媒体数据与数据库均使用道德经项目独立资源。
- 道场导航外跳高德地图或百度地图；不计算产品内路线和预计用时。

### 明确不做

- 话题、评论、回应、关注、私信、复杂通知、个性化推荐算法。
- 十万次累计展示、重复识别/后台合并、运营后台和核心人物标记 UI。
- 未来活动报名、RSVP、签到、成员名册及线上共读管理。
- AI 数据摄取、知识库索引、转写、摘要、问答和 Agent Harness 工程自动化。
- 管理员直接修改业务数据库之外的后台操作界面。必要的人员标签先留在后续需求中。

## 3. 开工前技术核对（Phase 0）

这些是有明确方向、但需依据现有实现作最后落地的事项；核对结果应补为 ADR 或更新本计划后再创建应用代码。

1. **仓库与家谱项目实现盘点**：核对 Node 版本、React 构建方式、Vercel Function 路由、Express 本地代理、workspace、Prisma 版本、认证模块边界、短信/邮件 provider 和媒体适配方式。
2. **隔离资源**：创建独立 Neon project/database 与开发/Preview/Production 环境；确定独立媒体存储账号/桶/凭据及生命周期。仅复用代码/技术，不复用实例、桶、账号或数据。
3. **定位与地图 ADR**：确定浏览器前台一次性定位、地理编码/逆地理编码、坐标系、最近道场匹配、街道级地址精度和高德/百度 deeplink 方案。定位授权被拒绝时，附近与临时地点功能不可用；经文和普通公开内容仍可浏览。
4. **媒体约束 ADR**：依据家谱项目实现选择同类技术并明确独立资源；确定允许媒体类型、上传大小/时长、格式、文件校验、公开读取和删除行为。媒体对象不能依赖不可撤销的永久公开 URL；隐藏后应停止应用端访问，并使用受控读取/短期签名 URL 或等效方案。上传通过签名或受限授权，不经常规 API 转发大文件。
5. **经典资料准备**：选择一份网络可获得的王弼本作为首版，记录来源、版本、获取日期和许可/使用说明。将章节内容作为独立、可替换的数据集导入，不把经文硬编码进页面组件。注释/解读如没有已确认来源，MVP 不伪造平台注释，可先标记待补。
6. **部署和密钥**：建立独立 Vercel 项目/环境与部署配置；确认 Neon pooled/unpooled 连接、邮件/短信服务凭据、JWT/HMAC、地图服务凭据和媒体凭据的环境变量清单。
7. **密码恢复口径（已确认）**：手机号注册时邮箱可选；手机号账号须先登录并绑定、验证恢复邮箱，之后才可通过邮箱找回密码。不提供短信密码找回。

## 4. 目标架构

按已确认的 Node.js + React 18 + Vercel + Express（本地）+ Prisma + Neon 方向，采用模块化单体：

```text
Responsive React app
       │ same-origin API
       ├── local: Express transport shell
       └── production: Vercel Functions
                    │
             shared handlers/services
               ├── auth adapter
               ├── domain modules
               ├── Prisma ── dedicated Neon DB
               ├── MediaStorage adapter ── dedicated object storage
               └── Geolocation/Maps adapter ── approved provider
```

沿用现有家谱项目实际构建与目录模式；不在未核实前把 CRA、具体 Node 小版本或某一媒体/地图供应商写死。浏览器不直连数据库或持有服务端密钥。数据库迁移以受控命令执行，不放进 Vercel build 隐式运行。

## 5. 分阶段编码计划

### 阶段 0：核对与 ADR

- 完成第 3 节资源、代码和内容来源核对。
- 更新架构 Spec 中被核实的运行时版本、构建命令、API 部署模式和媒体/地图 provider。
- 形成环境变量清单、数据备份/逻辑删除说明和原文导入说明。

**验收**：关键外部依赖有具体选择；独立数据库和媒体资源可供开发使用；经文种子数据有来源记录；未决项不阻塞基础应用初始化。

### 阶段 1：应用基础与账号

- 初始化响应式 React 前端及 Vercel API 入口；按现有项目建立本地 Express 传输壳和共享 handler。
- 创建独立 Prisma schema、Neon 迁移流程和环境配置。
- 从家谱项目迁移/抽取可复用认证代码到独立 `auth-kit` workspace，移除业务耦合并配置独立 provider 密钥。
- 实现手机号/邮箱验证码注册、手机号或邮箱密码登录、登出/会话读取、限流和密码找回。
- 手机号注册不要求邮箱；用户可在登录后的个人资料中绑定并验证恢复邮箱，之后通过该邮箱找回密码。未绑定已验证邮箱的手机号账号不能启动密码重置，也不能通过短信重置。
- 在账号设置中明确提示手机号用户：未绑定并验证恢复邮箱前无法找回密码；提供直接绑定/验证入口。
- 支持公开只读路由；发布、活动提交和道场维护 API 必须校验登录用户。

**验收**：匿名可访问公开路由；验证过的手机号或邮箱用户可完成注册登录和密码找回；手机号用户未验证恢复邮箱时不能重置密码，绑定并验证后可通过邮箱重置；认证凭据不进入浏览器持久化的非必要位置；开发/Preview/Production 配置隔离；代码路径不引用家谱数据库或认证数据。

### 阶段 2：经典阅读与可替换内容数据

- 定义版本/章节数据结构，导入 1—81 章首版王弼本文本及来源元数据。
- 实现“读书”默认 Tab、目录、章节阅读、上一章/下一章、字号调整和进度记忆。
- 为手机底部三 Tab（读书、发现、我的）及桌面响应式布局提供共用导航结构。
- 章节正文、来源、版本和后续替换采用数据读取，不把单一版本写死在 UI。

**验收**：匿名用户在窄屏和桌面均可打开 81 章目录并阅读；每章数据有可追溯版本/来源；替换或追加 TextEdition 不需重写页面组件。

### 阶段 3：账户资料、道场及定位发现

- 实现用户公开 profile 的最小字段和当前账号拥有权校验。
- 实现固定道场 CRUD：创建者维护名称、城市、介绍、活动方式、公开地址/联系方式；创建者关系可审计。
- 接入前台定位授权、坐标采集、地址解析和最近道场匹配；定位数据只在用户触发流程时采集。
- 未收录的临时地点可用定位生成，保存坐标、解析后的街道级地址、来源和维护者；对外展示地址，提供外部地图导航链接。
- 实现按城市、章节和道场的基础列表/筛选；附近结果依赖定位授权。

**验收**：道场创建者可维护自己的道场，其他账号不能越权修改；需授权定位的功能在授权后工作，拒绝时给出明确状态且不影响阅读；临时地点记录可区分固定道场 ID 与临时位置；不请求后台持续定位。

### 阶段 4：共读提交与章节分享

- 实现逐章共读记录提交。每个章节一条提交；服务端生成分钟级 `submittedAt`，以 UTC 存储并按 Asia/Shanghai 展示，客户端时间不作为权威值。
- 每次已登录用户提交都保留原始记录并计入原始提交数，不做重复检测、合并、管理界面或独立活动统计。
- 每次用户主动提交都新增记录；网络重试使用幂等键避免同一个 HTTP 请求被重复计数。用户再次主动提交使用新幂等键，仍作为新记录计数。
- 实现章节分享：文字必需，关联一个或多个章节；分享作者固定为当前登录用户；可选关联道场/共读记录。
- 实现可选图片、音频、视频原始文件上传到独立媒体存储；数据库保存元数据和对象引用。媒体发布默认公开，访问通过可撤销/短时授权控制，避免永久公开对象链接绕过隐藏状态。
- 发布者可隐藏自己的内容；隐藏立即从匿名公开查询、发现结果和媒体读取授权中移除。删除执行逻辑删除，不物理清除必要审计/tombstone；后续 AI 检索必须过滤。
- 为公开内容提供来源、作者、章节与提交时间展示。

**验收**：未经登录不能提交；多章提交生成多条逐章原始记录；同维度多人提交仍分别保留并各自计数；同一 HTTP 请求重试不重复计数；用户只能隐藏/管理本人内容；隐藏内容匿名读取和媒体访问授权立即不可见，逻辑删除后公开 API 不返回。

### 阶段 5：发现、发布闭环与部署准备

- 完成“发现”中的章节/城市/道场筛选和基础公开内容列表，不做个性化推荐。
- 完成“我的”中的个人资料、本人分享/共读提交列表和隐藏操作。
- 完成公开状态和定位说明、媒体上传状态、错误/空状态和授权拒绝提示。
- 配置 Vercel Preview/Production、数据库迁移、媒体上传域名/CORS、健康检查和基础错误日志脱敏。
- 编写运维手册：备份恢复、迁移回滚、媒体对象孤儿清理、逻辑删除、凭据轮换和人工数据库变更记录。

**验收**：从匿名阅读 → 注册登录 → 发布章节分享/共读记录 → 道场/城市/章节发现 → 隐藏本人内容的核心闭环可用；部署配置与数据资源独立；日志不含密码、验证码、完整 token 或签名 URL。

## 6. 数据模型落地提示

概念实体以[技术架构 Spec](./technical-architecture-spec.md)为准。编码计划实施时重点避免以下混淆：

- `UserAccount` 与公开 `UserProfile` 分离；手机号/邮箱认证身份不充当用户公开资料。
- `TextEdition` 与 `Chapter` 数据化；章节内容版本可切换。
- `Dojo` 固定道场与 `TemporaryPlace` 临时地点分开。
- `GatheringSubmission` 每次提交一条；一个章节一条；`submittedAt` 由服务端写入。
- `ContentItem` 章节分享与经文正文分离；作者来自认证用户 ID。
- `MediaAsset` 只存元数据和独立对象存储键；隐藏/逻辑删除状态参与所有查询过滤。
- 不实现合并后台，但保留后续建立重复/归并关系所需的稳定 ID 和来源字段；MVP 不预建复杂统计域模型。

## 7. MVP 交付验收总表

| 区域 | 最低验收结果 |
| --- | --- |
| 阅读 | 匿名移动/桌面浏览 81 章，版本来源可见 |
| 认证 | 手机或邮箱注册，手机号/邮箱登录；手机号用户可选验证找回邮箱 |
| 分享 | 登录用户发布章节分享，默认公开，作者可隐藏 |
| 活动 | 每次提交独立保存并计入原始提交数；服务端分钟级时间；按章分别提交 |
| 道场 | 创建者维护固定道场；附近/临时地点采集需定位授权；临时地址公开到街道级 |
| 发现 | 章节/城市/道场基础筛选，公开内容可浏览；外部地图跳转 |
| 媒体 | 通过项目独立媒体资源保存引用；隐藏/删除状态阻止公开访问 |
| 隔离 | Neon、媒体资源、环境密钥独立于家谱项目 |
| MVP 排除项 | 无评论/话题、推荐算法、合并/统计后台、运营后台、内置 ETA、AI/Harness 能力 |
