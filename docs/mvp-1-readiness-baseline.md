## 1. MVP 阶段边界

| 版本 | 范围 |
| --- | --- |
| MVP-1 | 匿名读经与信息框架；登录/注册；章节频道分享及互动；共读记录；道场/地图 POI 展示；建议入口并将 VOC 保存到数据库 |
| MVP-2 | 站内活动报名功能，独立补充活动生命周期、报名规则和通知验收 |
| 后续 | VOC 自动化分析/处置、Agent Harness、自进化、账号删除及其他逆向数据流程 |

MVP-1 必须保持可匿名阅读；AgentBot 导入可由游客直接公开，普通分享、评论、爱心、共读记录和需要身份的资料维护在触发时要求登录。认证模块属于重要能力，但优先级低于匿名阅读和信息架构骨架。

## 3. 开工检查清单

以下保留为开工基线检查项；2026-11-03 的实际实现、验收证据与外部依赖状态统一记录在[开发记录](./development-progress.md)。

### 3.1 产品与 Spec

- [ ] MVP-1 / MVP-2 范围表与所有主 Spec 用词一致。
- [ ] 产品故事均有唯一 ID、入口、前置条件、成功结果和失败/回退状态。
- [ ] 分享、评论、爱心、共读记录的登录门槛及登录后回跳一致。
- [ ] 地点是可选关联；无定位也能完成分享/记录所要求的章节流程。
- [ ] 管理员与创建者的内容管理范围明确，并可审计。
- [ ] 建议模块支持登录用户及游客提交；登录时可关联账号，游客不要求身份；原始建议不得作为 Agent 指令执行。
- [ ] UI 文案不把匿名分享描述为对平台匿名，也不把地图位置描述成必须提供。

### 3.2 技术与数据

- [ ] 盘点本仓库运行栈及家谱项目已验证的认证/短信/邮件/OSS/地图实现；只复用实现经验，不复用生产数据、凭据或资源实例。
- [ ] 确定开发、Preview、Production 的独立凭据和资源配置。
- [ ] 定义有效阅读触发条件及访客去重键；可见曝光与阅读分开，按 Asia/Shanghai 自然日去重；定义异常流量规则、重复上报幂等及排序边界。
- [ ] 定义内容软删除、管理员操作、媒体访问撤销和审计事件的最低实现；账号删除和备份清理不在 MVP-1。
- [ ] 先完成产品范围基线，再启动数据库实体/约束设计；schema 与迁移须评审后实施。
- [ ] 关键 API 契约、错误码、加载/空/拒绝/失败状态在任务中有对应验收场景。

### 3.3 AI Coding 就绪

- [ ] 任务切片能独立交付，有明确文件/模块边界、依赖、完成定义和验收命令。
- [ ] 每个业务任务关联 Spec 决策 ID 和测试用例 ID；AI 不得自行补充新的产品政策。
- [ ] 自动化验证覆盖核心用户旅程及权限边界；纯视觉/地图供应商行为保留人工核验步骤。
- [ ] 数据库迁移、密钥、短信费用、外部媒体资源等高影响操作须在任务描述中显式标记。

## 4. 用户故事与验收场景（候选）

| Case | 用户故事 / 场景 | 预期结果 |
| --- | --- | --- |
| AT-READ-01 | 访客打开读书、选择章节、阅读并前后章切换 | 无需注册；原文、版本/来源和阅读位置正确；公开频道入口可用 |
| AT-READ-02 | 访客从章节阅读进入该章频道 | 只显示当前章节公开分享；默认按有效阅读数降序；可切换最新 |
| AT-AUTH-01 | 访客尝试发表评论或发布分享 | 在写入前触发登录；成功登录后返回原章节/原操作；取消登录不丢失阅读上下文 |
| AT-SHARE-01 | 登录用户在当前章节发布文字分享，不提供位置 | 分享成功并出现在该章节频道；无地图 POI 关联 |
| AT-SHARE-02 | 登录用户提交分享时拒绝定位/无可用定位 | 允许继续；不生成虚构坐标或 POI；章节分享流程不受阻 |
| AT-POI-01 | 用户选择或确认有效 POI 并创建临时地点记录 | 临时地点在发现地图和列表显示并标注类型；POI ID 和来源一致，不变为固定道场 |
| AT-POI-02 | 设备坐标不能匹配有效 POI | 可移除地点后继续提交；不把近似坐标默认为确认 POI |
| AT-VIEW-01 | 同一访客在同一自然日内多次有效阅读同一分享，次日再次阅读 | 同日最多计一次，次日可再计一次；按 Asia/Shanghai 换日，累计阅读数不清零，重复上报幂等 |
| AT-VIEW-02 | 频道列表出现分享但卡片从未进入可见区域 | 曝光与有效阅读按事件定义分别处理，不因查询列表就自动累计阅读 |
| AT-SORT-01 | 多分享有不同有效阅读数与爱心数 | 主排序由有效阅读数决定；爱心数不覆盖该主排序；并列时使用已定义稳定次序 |
| AT-COMMENT-01 | 登录用户评论、删除自己的评论；另一用户尝试删除 | 作者可删除自己的评论；非作者无权删除；隐藏/删除的分享下评论不公开 |
| AT-CONTENT-01 | 创建者隐藏/删除自己的分享，随后使用之前获取的媒体访问地址重新请求 | 公开频道与后续媒体请求立即停止返回该内容；验证包括缓存命中和 Range 请求；已下载到设备的文件不属于服务器可撤回范围 |
| AT-CONTENT-02 | 普通用户修改他人内容；管理员管理任意内容 | 普通用户操作拒绝；管理员操作允许且生成审计记录 |
| AT-VOC-01 | 游客提交产品建议 | 数据库新增 VOC 记录，保留原始建议和创建时间，不要求身份；界面给出提交结果，不触发 AI 自动执行 |
| AT-VOC-02 | 登录用户提交产品建议 | 数据库新增 VOC 记录并关联提交账号，保留原始建议和创建时间；不触发 AI 自动执行 |
| AT-GATHER-01 | 登录用户提交共读记录，拒绝定位但提供章节 | 记录成功、服务端时间生成、无 POI 关联；其他用户的独立提交不合并 |
| AT-SIGNUP-01 | 新用户以手机号或邮箱注册并完成首个写操作 | 注册/验证成功后恢复原操作；登录与找回流程遵守已确认限额和隐私约束 |

## 6. 仍需在具体 Slice 设计时作出的决定

以下事项不推翻已确认产品方向，但需在相应任务进入实现前落定：建议提交后的用户可见状态回执；有效阅读的触发条件、访客去重键与异常流量规则；有效阅读数并列时的稳定排序规则；POI 选择/确认的交互方式；管理员身份如何安全配置与审计。涉及具体服务商费用、生产凭据或数据字段外发时先单独对焦。
