# MVP-1 数据库设计与基线对照

- 状态：实施设计 v1.0；2026-11-03 完成基线检查，已据此建立 schema/migration 并通过本地验证
- 适用：独立 PostgreSQL / Neon；与未经批准的 database-schema-spec.md 预研稿分开

## 数据实体和权限

| 模块 | 实体 | 必要约束 / 权限 |
| --- | --- | --- |
| 认证 | Account、AuthIdentity、Verification、RateBucket | 身份类型 + HMAC 唯一；验证码用途绑定、一次性消费、到期和失败次数；密码慢哈希；JWT 绑定 authVersion；手机号密码重置原子 24 小时额度 |
| 公开资料 | Profile | 与 Account 一对一；公开名称、内置头像；认证身份字段从不进入公开 DTO；角色仅服务端判定 |
| 经典 | Edition、Chapter、ChapterText、ChapterChannel | Chapter 1—81 稳定；频道一对一；文本按 edition + chapter 唯一，使用已有来源和状态；后续版本不覆盖既有文本 |
| 地点 | Dojo、TemporaryPlace | 固定道场与临时地点分开；地图仅绘制公开且有效 POI 的点；临时地点从属于一条记录，不转成固定道场；固定资料原始私密地址和联系信息仅用于内部来源追溯 |
| 共读 | GatheringSubmission | 单章节、唯一领读人名称快照、服务端时间、提交者；地点可空，也可关联固定道场或专属临时地点；重试幂等，不合并其他提交 |
| 分享 | ContentItem | 单章节、正文、作者、公开名称/匿名快照、可选来源/记录/道场、PUBLISHED/HIDDEN/DELETED；关联记录必须同章且有权使用 |
| 互动 | ContentLike、ContentComment、ContentView、Exposure | 爱心每账号/分享唯一；评论纯文本单层；所有公开查询回查父分享状态；阅读按分享、读者键、上海日期唯一，曝光独立记录 |
| 媒体 | MediaAsset | 独立存储对象键；上传者、类型、大小、PENDING/READY/HIDDEN/DELETED；可绑定一个分享；每次读取检查分享和资产状态；不保存签名 URL |
| 建议 | Feedback | 游客提交 accountId 可空；登录关联账号；保存原始建议、提交时间和状态；仅提交者/管理员可访问其记录，不公开建议正文 |
| 运维 | AuditEvent、IdempotencyRecord | 关键变更追加审计；幂等键绑定账号/访客、动作和请求哈希，同键不同内容返回冲突 |

## 状态、查询与并发

- 内容删除为逻辑状态更新；公开接口只返回 PUBLISHED，作者/管理员可查看管理状态。数据库保留数据，不实现账号删除。
- 读取媒体以数据库状态为事实来源。对象存储私有，下载由应用受控入口返回文件流，不向浏览器返回 COS 读取签名地址；Range 请求同样验权且响应不进入共享缓存。上传可用受限签名 PUT，完成时核对上传者、对象、实际文件大小/类型。
- 阅读详情可见连续 5 秒计一次有效阅读；进入列表只产生曝光。登录用户按账号去重，游客按第一方随机访客标识去重；有效阅读按 Asia/Shanghai 自然日划分。累计数不每日归零。
- 阅读插入和累计数更新在同一事务；唯一键抵御并发重试；同浏览器游客转登录时检查访客键，避免在身份切换时重复计数。跨设备游客身份无法自动合并，不使用指纹追踪。
- 手机重置额度由事务/条件更新检查上次成功时间，仅成功重置扣除；验证码消费与密码/身份写入同事务。数据库限流桶避免多进程绕过；服务商调用前执行限流。
- 幂等业务写入使用短事务和按主体/动作/幂等键的 advisory lock；外部服务调用不放在持锁事务中。
- 频道查询按 chapterNumber/status/viewsCount/createdAt/id 建索引；最新排序用 chapterNumber/status/createdAt/id；列表分页有数量上限。评论、媒体、地点维护和用户管理查询索引外键/状态字段。

## 对照已确认规则

| 基线 | 设计结果 |
| --- | --- |
| 读书先行 | 静态章节数据可先构建阅读；数据库只在后续持久化阶段启用 |
| 原文数据不擅自换本 | Edition 保存用户提供来源及状态；导入现有 YAML |
| 临时地点展示 | 保留临时实体，通过公开记录关联地图；列表区分 FIXED/TEMPORARY；没有有效 POI 不绘图 |
| 无定位继续 | GatheringSubmission 的地点关系可空，不建立虚假坐标 |
| VOC 游客与登录均可 | Feedback.accountId 可空；请求限流不依赖登录 |
| 按天阅读去重 | readerKey + contentId + readDay 唯一；日期来自服务器上海时区 |
| 显隐由数据库控制 | 查询和每次文件读取均检查状态；无公开存储读直链 |
| 创建者和管理员 | 修改用当前账号关系授权，管理员由服务端角色判定；匿名分享仍归属真实账号 |
| MVP-2 报名与 Harness 后续 | 本次不创建报名、录音、向量或 Harness 运行表 |

## 检查结论

已将最新产品决策逐项映射到实体和写入规则。创建 schema 前完成此独立设计；后续迁移仍需执行 Prisma 校验、空库迁移、种子导入和事务/权限集成测试。本设计不需要用户重新确认已定产品规则。
