# Agent Harness：面向 AI Agent 的整体工程架构方案（讨论稿）

- 状态：讨论稿 v0.1
- 日期：2026-10-31
- 适用项目：《道德经》公益在线共读平台
- 依赖：[proposal-spec.md](proposal-spec.md)、[design-guidelines-spec.md](design-guidelines-spec.md)
- 当前决策：仅作为未来技术方案参考，不属于本项目 MVP 编码范围

## 1. 目的与范围

本文定义 Agent Harness 作为平台 AI Agent 的运行与治理层。Harness 将用户任务转成受控、可追踪、可评估的执行过程；模型是可替换的推理组件，不是权限主体，也不构成内容权威。

本文只记录未来 Agent Harness 的技术方案参考。该方案不属于当前产品 MVP 编码范围，也不代表本项目立即建设工程自动化 Harness。平台 MVP 暂不建设 AI 数据接入、外部数据源连接器、平台内容摄取流水线或媒体 AI 处理。未来若单独立项工程 Harness 或面向平台内容的问答/转写，再分别定义数据范围、授权、保留和处理边界。Agent Harness 不负责经典文本定稿、活动真实性判断、身份认证、道场维护或未经授权内容的公开发布。

## 2. 设计目标与非目标

### 2.1 目标

- 每次运行都能解释谁发起、代表谁、使用了哪些资料和工具、产出了什么，以及成本与结果。
- 所有检索和工具操作执行服务端授权；模型不能扩大调用者权限。
- 对可核查事实给出可打开的来源引用；依据不足时澄清或拒答。
- 支持人工复核、反馈、删除/授权撤回后的派生数据清理，以及模型/提示/索引版本回溯。
- 通过稳定内部接口切换模型供应商、检索实现和部署形态，不改变既有 Web/API/Prisma/Neon 架构。

### 2.2 非目标

- 不做可自由规划并任意调用互联网、代码执行、邮件、社交平台等工具的通用 Agent。
- 不让 Agent 自行修改用户、角色、授权、地点、活动计数、经典正文或公开状态。
- 不承诺模型提供权威经义解释；首期回答范围是平台中已授权、已归档的内容。
- 不把模型自报置信度当作正确性证明。
- 不默认将完整用户资料、原始音视频或无关历史对话发送给外部模型。

## 3. 关键术语与边界

| 概念 | 定义 |
| --- | --- |
| Agent | 面向某类任务的策略与流程配置，不是独立权限身份 |
| Harness | Agent Harness 执行控制面：身份上下文、策略、检索、工具路由、模型调用、校验、审计、评估 |
| Tool | Harness 暴露给 Agent 的窄接口；有输入 schema、授权规则、副作用等级和审计事件 |
| Run | 一次完整任务执行及其阶段事件、输入输出引用、版本与资源用量 |
| Evidence | 支持输出主张的最小来源单元，可指向文本片段、内容条目、章节或媒体时间段 |
| Derived artifact | 转录、摘要、标签等派生数据，记录父子关系、授权继承和清理状态 |

权限主体始终是经过认证的用户、系统任务服务或经明确配置的运营人员。Agent 不能自行取得身份、同意或更高角色。

## 4. 分阶段能力范围

| 阶段 | 能力 | 执行方式 | 用户可见性 |
| --- | --- | --- | --- |
| A：Harness 工程验证 | 五大模块、Run 记录、评估/错误闭环、隔离代码变更与资源治理 | 面向工程任务的受限上下文；隔离环境 | 内部工程流程 |
| B：平台数据能力评估 | 如未来决定启用平台资料问答或媒体处理，先单独定义数据授权/访问策略并验证 | 另行设计接入与权限边界；本 Spec 不预设实现 | 不在当前范围 |
| C：受控产品能力 | 经独立评审后开放特定面向用户的 Agent 能力 | 专属策略、工具、评估集与灰度 | 逐项批准 |

阶段 B/C 不自动由阶段 A 推进。进入平台数据能力开发前，必须另行确认数据源范围、授权主体/用途、删除传播、模型供应商数据处理、检索权限与评测集；本阶段只为将来保留适配接口，不预建摄取服务或索引。

## 5. 核心交互契约

### 5.1 未来平台内容问答的流程参考（非当前实现）

1. API 验证用户会话，建立不可由模型修改的 principal（用户/角色/组织范围）和请求关联 ID。
2. 策略层校验功能开关、速率和配额、任务允许的资料类型，以及敏感数据处理规则。
3. 检索服务先按数据库事实权限过滤，再返回候选 evidence；不得先做全库向量搜索后仅靠提示词要求模型忽略越权结果。
4. 证据打包器只发送完成任务所需的片段、元数据和来源定位；用户问题及检索文本均视为不可信内容。
5. 模型生成结构化回答草稿及主张—证据关联；模型没有可直接调用的任意工具能力。
6. 输出校验器检查引用 ID 属于本次授权检索结果、来源仍可见、必需主张有证据、内容标签和长度合规。
7. 校验通过后返回回答与引用卡片；若证据不足则返回澄清/拒答。失败结果不得伪装成已核实答案。
8. 记录最小审计事件与用量；提供有帮助/无帮助、引用错误、隐私/授权问题等结构化反馈。

### 5.2 未来平台数据处理的设计门槛（非当前实现范围）

未来若处理平台内容或媒体，需先由独立产品/隐私决策明确数据来源、允许用途、用户授权、派生物可见性、保留/删除和人工复核，再设计具体处理流程。本 Spec 当前不建设该摄取/处理流水线，也不默认为已有 Consent 记录足以授权模型处理。

## 6. 工具与权限模型

工具按能力白名单注册，并以代码定义 schema 和服务端授权检查。以下是未来平台内容型 Agent 的候选工具，当前不实现、不开放，也不因该清单预设 AI 数据授权：

| 工具 | 权限/副作用 | 约束 |
| --- | --- | --- |
| search_authorized_content | 只读 | 服务端按用户、角色、可见性、授权状态过滤；限制结果数与字段 |
| get_source_excerpt | 只读 | 校验 evidence 仍可访问；只返回必要片段和来源定位 |
| submit_feedback | 写入低风险反馈 | 用户确认后写入；不能修改来源内容或授权 |
| create_draft_artifact | 有副作用、仅后台任务 | 写入待复核草稿；不可改变原文、公开状态或活动数 |

当前工程 Harness 可用的开发工具集（如代码检索、受限文件编辑、检查命令）应在独立的工程 Agent 工具策略中定义，并受隔离工作区、允许命令、网络范围和 Resource Governor 约束。平台内容型工具当前不开放。未来所有写操作需显式业务 handler 再次授权并记录操作者、对象、理由和结果。Agent 输出中的工具调用字段只是数据，只有 Harness 能决定是否执行。

## 7. 内容信任与引用协议

### 7.1 内容类型

所有上下文保持显式类型：CLASSIC_TEXT（版本与章节）、VERIFIED_NOTE（作者/校订/来源）、PLATFORM_EDITORIAL、USER_CONTRIBUTION、AI_DERIVED。不能因语义相似或模型归纳而改变来源类型。回答 UI 应区分直接引文、忠实转述和模型综合说明。

### 7.2 引用结构

每个 evidence 至少包含：稳定 ID、源对象类型及 ID、可见性/授权检查结果引用、作者或整理者、内容版本/更新时间、章节关联、文本偏移或媒体起止时间、可供用户打开的内部链接。回答每个可验证主张携带一个或多个 evidence ID；UI 展示来源标签及上下文入口。不得只给无法定位的文末链接。

引用定位以应用源数据为准，不保存模型改写文本作为唯一来源。索引重建后 evidence ID 可更新，但已有 run 审计应能回溯当时命中的源版本和片段摘要，并遵守保留/删除策略。

## 8. 数据与运行记录

建议新增概念实体，具体落表前依据数据保留与隐私决策裁剪：

| 实体 | 关键字段 |
| --- | --- |
| AgentDefinition | id、任务类型、启用状态、策略版本、默认模型路由、输入/输出 schema 版本 |
| AgentRun | id、发起 principal、任务类型、状态、开始/结束时间、策略/提示/模型/索引版本、token/延迟/成本估算、错误类别 |
| AgentRunEvent | run_id、阶段、时间、工具名、结果状态、脱敏摘要、关联对象；不默认留存完整敏感提示词 |
| EvidenceSnapshot | run_id、源对象和版本、片段定位/摘要、检索顺序及权限决策版本 |
| DerivedArtifact | 源对象、处理类型、内容版本、父派生、授权用途、复核/发布状态、清理状态 |
| AgentFeedback | run_id、提交人、反馈类别、可选说明、处置状态 |

避免把完整提示词/回复、手机号、邮箱、私密原文写入高可见性日志。调试样本应单独设置授权、脱敏、访问控制和期限。运行记录不得成为绕过来源删除要求的第二份内容库。

## 9. 整体工程架构

### 9.1 架构决策

- 沿用 Node.js 20+、React 18 SPA、Vercel Serverless Functions、Express 本地传输壳、Prisma、Neon PostgreSQL。
- 先做模块化单体：Harness 与现有 API 在同一代码库、服务端以明确模块边界实现；不因 Agent 名称预先拆微服务。
- Agent 定义、策略、工具契约和执行状态由应用管理；LLM 仅通过 Model Adapter 提供受限推理。
- 工程任务提交/状态查询与长时隔离执行分开；当前不接入平台内容问答或媒体处理。
- 授权过滤必须发生在检索候选暴露给模型之前；向量索引只负责召回，不是权限事实来源。
- 定义本地接口与版本化请求/响应契约；首期只接一个已批准模型和一种实际需要的检索方案。

### 9.2 逻辑组件与依赖方向

```text
React 18 SPA
  │ HTTPS / session token
  ▼
API 边界（Vercel Function；本地由 Express 挂载相同 handler）
  ├─认证与主体解析
  ├─输入 schema、速率/配额、功能开关
  ▼
Agent Harness 应用模块
  ├─Run Manager：创建运行、状态与幂等
  ├─Policy Engine：任务策略、数据范围、工具白名单、预算
  ├─Context Builder：授权检索、证据组装、脱敏
  ├─Agent Runtime：有界步骤执行、超时/取消
  ├─Tool Registry：已注册工具及每次调用授权
  ├─Model Gateway：模型路由、结构化输出、重试/熔断
  ├─Output Guard：schema、引用、拒答与安全校验
  └─Telemetry：Run、事件、反馈、指标
       ├─Domain Services / Prisma → Neon PostgreSQL
       ├─Retrieval Adapter → 预留接口；平台内容检索不在当前阶段实现
       ├─Model Adapter → 经批准的外部/自托管模型
       ├─Blob Adapter → 复用家谱项目的媒体技术方案，连接道德经独立媒体资源（Harness 当前不摄取或处理媒体）
       └─Job Adapter → 队列与 Worker（长任务）
```

依赖方向由 Harness 指向接口，由具体适配器实现接口。模型适配器不能直接读写数据库；工具不得绕过领域服务；UI 不直接连接模型、向量库或对象存储。Express 与 Vercel 只负责传输和运行时适配，应复用相同 API handler 与业务模块。

### 9.3 请求与执行生命周期

**工程任务**：受信入口校验任务 principal 与工作区策略 → 建立 Run/Job 和 request ID → Resource Governor 检查预算 → 隔离 Worker 执行允许的代码检索/编辑/检查步骤 → Judge 判定并记录错误/资源 → 返回结果或候选变更集。短请求只创建任务或查询状态；执行有硬截止时间、步骤和资源上限。

**异步任务**：API 验权并创建幂等 Job/Run → 返回 job ID → Worker 领取并租约执行 → 每阶段保存状态与可恢复检查点 → 成功/失败/取消结果落库 → 客户端轮询状态或后续接通知。重复投递不得重复创建公开内容；重试只针对幂等阶段，外部调用需有 attempt ID。

状态至少区分 QUEUED、RUNNING、SUCCEEDED、FAILED、CANCELLED。策略拒绝和用户取消不可当成系统失败重试。每次运行设置最大步骤数、最大工具调用数、最大上下文量、模型 token 预算和 wall-clock 截止时间。

### 9.4 服务接口契约

以下业务 Agent API 仅作为未来集成参考，不属于当前 AI 数据接入或功能实现。当前工程自动化入口应使用受信工程任务接口，并以独立策略约束工作区和命令。

| 接口 | 用途 | 约束 |
| --- | --- | --- |
| POST /api/agent/runs | 发起允许的短问答或明确类型任务 | 用户会话；服务端选 agent/policy；客户端不能提交角色、工具清单或模型供应商 |
| GET /api/agent/runs/:id | 查看本人或有权管理的 Run 状态/结果 | 对象级授权；敏感内部事件不返回普通客户端 |
| POST /api/agent/runs/:id/feedback | 提交结果反馈 | 仅允许反馈当前用户可访问的 Run |
| POST /api/internal/agent/jobs | 由受信业务流程创建后台 Job | 服务间认证；不公开给浏览器 |

请求/响应使用版本化 schema，统一 request ID、错误码和结果状态。同步响应只返回展示所需结果与 evidence 引用，不泄露隐藏检索片段、系统提示或供应商原始响应。

### 9.5 领域数据、Run 与索引边界

- PostgreSQL 是权威来源：用户、角色、内容可见性、授权、原文版本和派生状态都以事务数据库为准。
- Harness 表只记录执行面：AgentDefinition/策略版本、AgentRun、RunEvent、Evidence 引用、ToolInvocation 摘要、Feedback、Job 状态。不要把领域模型复制成第二套真相。
- 索引为可重建派生物：保存 source ID、source version、内容类型与授权过滤字段；删除/撤回先使数据库状态不可检索，再异步清索引并验证。
- Run 默认保存引用 ID 和版本/定位；正文快照只有在审计确有必要且经过保留决策后才保存。
- 提示模板、策略、模型路由有版本；API 凭据仅服务端可读，不进数据库明文、客户端包或日志。

### 9.6 检索与授权执行

当前阶段不连接平台内容检索或向量索引。未来若立项平台资料问答，可先评估 PostgreSQL 全文检索与结构化权限条件，再根据评测决定是否增加向量召回；任何候选都需回源复查当前授权、可见性和删除状态。这里是未来准入原则，不表示已有 AI 数据接入范围或授权机制已经确定。

索引更新采用可重放事件或 Outbox 模式，避免数据库提交成功但索引更新丢失。删除/撤权先拒绝访问、后清理派生索引；清理失败进入可观测重试队列并告警。

### 9.7 部署拓扑与演进

| 阶段 | 部署拓扑 | 用途/限制 |
| --- | --- | --- |
| 原型与短问答 | React 静态站点 + Vercel API Function + Neon | 适合短请求；按实际函数时限设置模型超时与预算 |
| 内部异步试点 | 受信工程入口创建 Job；持久队列 + 隔离 Worker；Neon 保存状态 | 用于代码评测、候选变更和长时工程任务；队列/Worker 供应商待部署约束与预算确认 |
| 扩展阶段 | 需要时将高负载检索、媒体处理或 Harness Worker 独立部署 | 由延迟、吞吐、隔离或供应商限制数据证明后拆分 |

**对抗性检查**：若把隔离代码评测和候选变更都放在 Vercel 请求函数里，长时间运行、重试或进程中断会导致任务重复、状态丢失和成本不可控。因此短 API 只创建任务/查询状态；工程评测和候选变更使用持久 Job 状态与隔离 Worker。队列和 Worker 供应商不在当前技术 Spec 中预设，需在工程自动化试点前按部署/预算选定。

### 9.8 可观测性、弹性与成本

- 每个请求跨 API、Run、检索、工具和模型调用贯穿 request ID / run ID；记录阶段耗时、状态、模型路由、检索数量、token 与成本估算。
- 指标覆盖运行量、成功/拒答/错误率、P50/P95 延迟、供应商错误率、检索无结果率、引用校验失败率、预算消耗与 Job 队列年龄。
- 对模型供应商设置连接/总超时、并发上限、有限重试、熔断和 feature flag；不自动降级到未评估模型。
- 异步 Job 采用退避重试、最大尝试次数和死信/人工处置状态。
- 对用户与任务类型设置速率和预算上限；达到系统成本阈值时限流或关闭 AI，不影响经典阅读、活动登记等非 AI 路径。

### 9.9 模块建议

代码按职责拆模块，而不是按模型供应商拆目录：

```text
api/                         Vercel transport handlers
server/                      Express transport shell
lib/agent-harness/
  contracts/                  请求、响应、Tool、Model、Retriever 类型
  application/                Run Manager、编排用例、策略流程
  policy/                     principal、数据范围、预算和功能策略
  tools/                      只读检索、引用读取、反馈、草稿工具
  retrieval/                  Postgres 检索及索引适配器
  models/                     模型 gateway 与供应商适配器
  safety/                     输入/输出、引用、提示注入边界检查
  persistence/                Prisma repository 与 Run/Job 存储
  observability/              事件、指标、脱敏日志
```

这是目标模块边界，不要求一次性建立全部目录。首期可先实现少量职责清楚的模块；确认多应用复用需求后再抽成 workspace package。

### 9.10 五大核心模块

Agent Harness 的核心不是“能调用模型”，而是围绕目标、证据、失败和预算形成可验证的执行控制面。五个模块共同作用于每一次 Agent Run：

| 核心模块 | 职责 | 输入 | 输出 / 可验证结果 |
| --- | --- | --- | --- |
| 方向指引（Direction） | 将产品目标、任务边界、内容信任规则编译为任务策略、Agent 指令、允许资料类型和完成标准 | 已批准的产品 Spec、政策版本、任务类型、principal | 版本化任务契约；每次 Run 可追溯使用的目标与策略版本 |
| 结果判定（Evaluation / Judge） | 用确定性校验与评估器判定输出是否满足任务完成条件 | 用户请求、运行轨迹、工具结果、输出、evidence、评测集 | 结构化判定：通过、拒答、需复核、失败；分项原因和评估版本 |
| 错误记录（Error & Learning Data） | 归类运行失败、越权拒绝、引用问题、用户纠错、资源超限及人工复核结果 | Run 事件、校验结果、反馈、系统错误 | 可追踪错误样本、根因分类、复现所需的非敏感元数据与处置状态 |
| 自进化（Evolution） | 从重复错误中形成评测样例、策略/提示/工具/代码改进提案，在隔离环境验证并比较基线 | 已审阅错误样本、版本化评测集、代码/配置变更 | 可审阅的改进变更集、评测报告、回滚点；不得自行发布 |
| 资源边界（Resource Governor） | 在请求执行前后限制模型、检索、工具、并发、时限和花费 | 用户/任务配额、系统预算、运行状态、供应商状态 | 允许/拒绝/限流/停止决定；超限原因与资源账本 |

#### 模块边界与控制权

- Direction 的规范来源是经批准并版本化的产品/治理决策；模型生成的计划不能覆盖任务目标或权限策略。
- Judge 采用“确定性规则优先、模型评估辅助”的分层方式。授权、schema、引用 ID、预算和状态机由代码规则判定；语义质量可由模型或人工辅助，但不能单独放行安全边界。
- 错误记录需区分模型质量问题、检索/数据问题、策略拒绝、用户输入不足、供应商/平台故障和资源耗尽，避免把拒答误记成模型失败。
- Evolution 可生成测试、提示/策略候选和代码变更提案；更改目标、Judge 放行门槛、工具权限、数据授权规则、资源上限及生产密钥权限属于受保护控制面，必须由指定维护者审阅批准。
- Resource Governor 是独立于 Agent Runtime 的外层约束；模型不能请求提高自身预算，也不能通过重试、拆分任务或委托子 Agent 绕过全局配额。

### 9.11 可持续进化与自动化开发闭环

目标是逐步实现“自动发现改进机会、自动准备代码变更、自动验证、受控交付”的工程自动化；不是让生产 Agent 无监督地改写自身并直接发布。

```text
目标/Spec 版本
  → 任务运行（Run + Trace + 资源账本）
  → 结果判定（规则 / 评估 / 人工反馈）
  → 错误样本归档与去重
  → 形成可复现评测案例
  → Evolution 生成改进提案/代码变更
  → 隔离分支或临时工作区执行静态检查、自动化评测与安全检查
  → 与基线比较：质量、越权、成本、延迟、回归
  → 达到门槛后提交待审 PR / 发布候选
  → 负责人批准后合并与灰度；监控指标并支持回滚
```

#### 自动化开发阶段

| 等级 | 自动化范围 | 放行条件 |
| --- | --- | --- |
| 0：可观测 | 自动记录运行、错误类别、成本和反馈；人工修复 | 数据完整性和脱敏规则通过审查 |
| 1：改进建议 | 自动生成评测案例、提示/策略建议和根因摘要 | 人工确认样本标签，避免把错误反馈当真值 |
| 2：隔离变更 | Agent 在隔离工作区修改代码/配置并运行项目检查、评测和差异分析 | 变更受限于允许文件/命令；无生产凭证；资源配额生效 |
| 3：候选交付 | 自动建立可审阅的变更集/PR，附测试结果、风险、基线对比和回滚说明 | 代码所有者审核；高影响策略及权限变更需额外负责人审核 |
| 4：有限自动发布 | 仅适用于已批准、低风险、可快速回滚的规则或内容处理配置 | 单独的风险分类、灰度、告警、回滚演练与明确授权 |

首期目标建议设为等级 0—2；等级 3 在隔离执行、评测集和代码审查流程稳定后启用。等级 4 不作为首期目标，且不涵盖权限、策略放行标准、认证、数据治理或高影响生产代码。

#### 进化评估与准入标准

- 每个改进提案绑定一个或多个已复现错误样本，并说明预期改变的指标。
- 评测集采用固定回归集加独立留出集；提示或策略调优不能访问用于最终准入的留出答案。
- 新版本必须同时报告任务成功率、支持性正确率、拒答质量、权限隔离、引用有效性、成本和延迟；不能以单一满意度或成功率抵消安全回归。
- 权限隔离出现任何回归、引用/授权校验绕过或敏感信息泄露即阻断候选；质量提升不能抵消这类失败。
- 记录变更前后版本、数据集版本、运行环境、随机种子/模型路由（若可用）、判定结果、审阅人与回滚目标。
- 错误样本可能含有个人信息或授权内容，入库前需最小化和脱敏；样本的保留、删除和访问策略继承对应数据治理要求。

#### 自进化的对抗性边界

自进化很容易把“改善指标”变成“迎合指标”：例如降低判定严格度、扩大拒答范围、隐藏错误样本或只优化常见问题。防护方式是把目标/判定门槛与待优化 Agent 隔离；设置独立留出评测、错误类别覆盖率、分层指标和审计；任何改变评测标准的变更作为治理变更单独审批，不能由 Evolution 自动批准。自动生成的代码只在无生产凭证、受限网络和有资源配额的隔离环境中执行。

模型调用前的最小数据包由任务策略控制。未完成供应商数据驻留、留存、训练使用及跨境评估前，阶段 B 仅允许使用已批准的内容范围和供应商配置；不可把 API 密钥暴露到客户端。

## 10. 失败处理与安全基线

- 超时/供应商错误：有限次数重试；使用带关联 ID 的可理解错误，不返回半截答案。
- 检索为空、冲突或证据不足：明确表示平台资料未找到足够依据，可建议缩小问题或查看相关章节。
- 越权结果、无效引用或校验器异常：整次输出失败关闭，记录安全事件，不回退到无引用生成。
- 提示注入：资料文本与用户输入均为数据而非指令；工具权限不从文档内容推导；检索片段采用隔离标记和长度限制。
- 个人信息：按最小必要原则裁剪；位置、身份联系方式及可识别媒体除非任务必要且获准，不进入模型上下文。
- 撤回/删除：先禁止新检索和输出，再清理缓存/索引/派生物；审计只保留满足调查与法定义务的最少不可逆元数据，具体期限需决策。
- 模型/提示/索引版本：每次 run 可追溯；供应商故障时可关闭功能或切换到已评估路由。
- 不支持由模型自主决定发布或执行身份、授权、统计等高影响操作。

## 11. 可度量验收指标

若未来提议启用平台内容型 Agent，试点前需建立冻结评估集，记录问题、允许资料范围、期望行为、必要引用和拒答标签。以下是该未来能力的候选放行阈值，不是当前工程 Harness 上线门槛；调整需留版本记录：

| 指标 | 定义 | 未来内容型 Agent 候选门槛 |
| --- | --- | --- |
| 授权隔离正确率 | 越权探测中未暴露禁止资料的比例 | 100%；任何泄露阻断放量 |
| 引用可解析率 | 输出引用 ID 均存在且用户可打开 | ≥ 99% |
| 有据回答引用覆盖率 | 有事实主张的答案中，每项主张有支持来源的比例 | ≥ 95% |
| 支持性正确率 | 人工评审答案是否被引用内容支持 | ≥ 90% |
| 拒答/澄清质量 | 无依据问题是否避免编造，并给出合适下一步 | ≥ 90% |
| 删除传播 | 撤回/删除后新请求不再返回该内容或派生物 | 100% 按目标时限完成 |
| 运行可追溯率 | run 记录所需版本、principal、工具结果状态 | 100% |
| 延迟与成本 | 成功率、P50/P95 延迟、每次成本按任务类型分布 | 试点前定预算；超预算自动限流/关闭 |
| 错误复现率 | 已归类且可复现错误中，进入版本化评测集的比例 | 趋势提升；不得为 0 且不报告样本量 |
| 同类错误复发率 | 已标记修复的问题在后续固定回归集/生产抽样中的复发比例 | 按错误类别分层，版本间不恶化 |
| 改进净收益 | 候选版本相对基线在质量指标的变化，同时报告成本/延迟/拒答变化 | 至少一项预定目标改善，安全指标无回归 |
| Judge 一致性 | Judge 与人工复核在通过/拒绝/需复核标签上的一致比例 | 试点期持续校准并按任务类别报告 |
| 资源限额遵守率 | 超出硬预算后未继续发起模型/工具调用的比例 | 100% |
| 回滚恢复时间 | 从触发回滚到恢复上一个已批准版本的时间 | 设定并演练目标；每次演练留记录 |

评估按内容类别、问题类型、权限边界和模型版本分层报告，不能只报告总平均分。人工评估样本需保留判定指南及分歧仲裁记录。

## 12. 对抗性审视与待共同决策

这些问题会改变架构或用户承诺，不能靠实现细节默认带过：

1. **逐条引用是否真能证明答案？** 若未来启用内容问答，有引用仍可能错引、断章取义或把相关性当支持。需要决定对每个主张做评测，还是先限制为检索摘录与摘要，并明确引用支持性门槛。
2. **工程任务的外部模型处理边界是什么？** 即使当前不接入平台内容，代码和错误记录也可能包含敏感信息。需明确工程上下文的最小化、供应商留存/训练政策与凭证隔离。
3. **自进化如何防止迎合指标？** 如果 Agent 能调整目标、评判门槛或错误样本，可能通过降低标准制造“进步”。目标与判定门槛需独立版本化，留出集和权限硬门槛不得由 Evolution 修改。

## 13. 建议默认决策

- 未来若单独立项工程 Harness：可从工程内能力验证开始，不连接业务内容数据，不运行内容问答、转写或摘要任务。该项不在当前产品 MVP 计划中。
- 后续如启动平台内容型 Agent，先批准数据源、处理用途、授权和模型供应商边界，再定义内容类型、引用、拒答和人工复核规则。
- 工程变更：只在隔离工作区生成候选变更，不直接写入受保护分支或生产环境；变更需通过独立 Judge、评测和负责人审核。
- 平台数据：当前不向 Agent 开放业务内容读取或写入；未来启用平台内容型 Agent 前，需单独批准授权、范围和处理边界。
- 工具与资源权限：服务端策略和 Resource Governor 约束工程工具；模型无权扩大主体权限、工作区范围或预算。
- 架构：先做模块化单体与清晰 adapter 接口；只有吞吐、隔离或部署约束被实测证实时再拆服务。
- 交付：候选变更达到自动化级别对应的评测与审批门槛后，按代码审查和发布流程交付；生产变更需保留灰度与回滚能力。

## 14. 将来单独立项时的交付建议

1. 工程负责人先落地五大模块的最小纵切：方向策略版本、Run 判定、错误分类与反馈、预算硬限制、评测候选工作流。
2. 建立针对工程任务的固定评估集与红队问题集；以等级 0—2 为目标完成观测、建议与隔离变更验证。
3. 未来若单独立项，核对家谱项目的媒体技术方案并用于道德经独立媒体资源；不复用家谱媒体实例，不启用 Harness 媒体读取/处理。
4. 未来若提出平台内容型 Agent，再立项确认数据源、授权、处理目的、模型出域、保留/删除与审核责任。
5. 在工程自动化试点中记录指标、样本、已知限制；达到条件后再评估候选交付等级 3。
