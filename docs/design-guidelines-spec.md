# 《道德经》共读平台统一设计 Spec

- 状态：MVP-1 统一设计出口 v1.1
- 日期：2026-11-01
- 更新：2026-11-13
- 依据：[`docs/proposal-spec.md`](./proposal-spec.md)
- 适用范围：响应式 Web 产品的设计原则、页面布局、阅读排版、交互层级与验收标准；不替代业务规则、内容校勘或数据来源要求
- 设计目标：以移动端为优先，同时让桌面端适合长文阅读、内容发现与资料管理

本文件是本项目新增页面和既有页面视觉调整的统一设计出口。业务规则以 [MVP-1 readiness baseline](./mvp-1-readiness-baseline.md) 与产品 Spec 为准；页面职责以本文件第 4、5 节和 [产品页面动线 Spec](./product-page-flow-spec.md) 为准；阅读手势与浮层状态以 [移动端阅读体验 Spec](./mobile-reading-experience-spec.md) 为准。发生冲突时，业务正确性、内容来源与用户已确认要求优先于视觉示例。

## 0. 统一设计原则

1. **阅读优先，古典元素克制**：用纸白底色、近墨正文、宋体/衬线正文和充足留白建立安静感。印章色仅作少量语义强调；不以仿古纹理、书法字或装饰性边框模拟古籍。
2. **内容结构表达语义**：标题、正文、注释、来源和分享各有稳定层级。优先用行距、段距、细分隔线和对齐关系组织内容，不将长文拆进连续卡片。
3. **桌面扩展，移动收敛**：桌面可使用多列呈现并列关系；窄屏回到单列、原阅读顺序和自然换行。不得为保留桌面构图而压窄正文、缩小字号或引入横向滚动。
4. **来源与内容不可被视觉混淆**：经文、现代注释、传统注本、用户分享必须使用明确标签/位置区分；颜色只能辅助区分，不能单独承担语义。
5. **无损呈现原文**：视觉分段不得增删、改写、重排经文字符和标点。无法可靠识别结构时回退连续原文；不将视觉处理伪装成底本校勘。
6. **信息节制且可验证**：不添加虚构来源、作者、热度、审校状态或功能。字号、对比度、重排、键盘/屏幕阅读器顺序与可操作范围纳入验收。

### 0.1 阅读排版基线

- 页面底色沿用项目纸色 token，正文使用近墨色 token，次级说明使用可读的 muted token；新样式必须复用现有变量，不散落硬编码色值。
- 原文默认 20px、行高约 1.9；字号档位沿用 18/20/22/24px。字型随平台回退但必须可读，不依赖用户设备上的单一字体才能正确分页。
- 375 CSS px 视口下正文左右内边距目标约 24px；窄屏允许收至约 16–20px。桌面阅读正文可扩大可用宽度，但单行不应无限延长；并列版式只用于内容本身成组或对照的场景。
- 章节层级为：轻量导航 → 章节标题/来源 → 原文 → 页码/章节动线 → 注释与分享辅助层。原文不包卡片；分组以留白和细线为主。
- 对比色强调每个阅读单元最多一类重点；禁止整段高亮、同时多色争抢、仅靠色彩编码语义。
- 具体交互、手势和状态沿用 [移动端阅读体验 Spec](./mobile-reading-experience-spec.md)，本文件不另造冲突的控制规则。

### 0.2 第十章排版样例与复用边界

第十章作为首个结构化原文样例：六个连续自问在桌面宽屏以两列、按原文顺序阅读；手机改为单列。末段“生之畜之”独立起行，后续三个“不占有 / 不自恃 / 不主宰”句作为唯一重点使用印章色，末句“是谓玄德”回归正文色。组间用留白和一条细线，不做卡片。

这套样式只适用于可由文本标点稳定识别、内容成组关系明确的章节。不能把“六问 + 收束”机械套给其他章。文字字号变大、视口变矮或布局无法完整呈现结构时，按原有分页机制回退到连续原文；禁止截断。后续章节须先证明其语义分段及断点，再决定是否复用结构化版式。

验收关注：原文字符与顺序逐字一致；桌面双栏阅读顺序仍按左列后右列与原文一致；手机单栏无横向溢出；默认字号下不遮挡页码及注释浮层；大字号下完整可翻页；辅助技术读取顺序与原文一致。用户验证时记录找句时间、回看/跳行情况及主观费力程度，不用“更好看”代替可读性结论。

## 1. 设计任务与产品重心

首期产品围绕三个相连但边界清晰的任务组织，定位偏内容并带有适度社交属性：

1. **读经典与章节频道**：快速找到 1—81 章，连续阅读原文、注释与解读，并进入对应章节频道浏览和贡献内容。
2. **发现到场道场**：打开地图或按省、市查看已收录道场地址。首期“发现”Tab 不承载洞察内容流、跨章节分享发现或推荐。
3. **管理个人贡献**：查看本人资料与分享/记录，隐藏或逻辑删除本人分享。

章节频道是持续承载章节分享的长期空间；活动记录是独立对象。活动记录不是签到、到场证明或活动审批。布局与交互不得让用户误以为必须预登记、签到、上传媒体或等待组织者确认，才能发布或提交记录。

### 1.1 影响路径（线框图的验证主线）

```mermaid

  D --> E[自愿分享文字或音频]
```

## 2. 设计原则

### 2.1 阅读优先，降低进入成本

- 全局首要入口是“读书”；阅读是首期最稳定、最常用的核心路径。“发现”首期聚焦道场地图/省市列表，不设置独立首页推荐流。
- 目录按第 1—81 章顺序呈现，采用清晰的章节索引行和轻分隔线，不使用卡片墙；提供明确的当前阅读位置和快速跳章方式。
- 章节页优先呈现原文；注释、解读与共修分享在视觉层级和内容标签上明确区分。
- 阅读过程中提供目录、翻页与进度记忆；章节注释、频道和本章分享清楚可见，字号等设置收进次级菜单。
- 阅读采用书籍式连续正文与编辑式留白，不把经文、注释和段落拆成连续的小卡片；层级靠字号、行距、段前段后距、章节编号和轻分隔线表达。
- 阅读页是沉浸的正文画布：保留原文行句关系；底部常驻非模态浮条，可展开查看本章注释和频道分享，用户分享与原文分开。

### 2.2 内容来源与身份清楚可见

- 原文、注释、平台编辑说明、用户分享和 AI 派生内容使用不同的内容类型标识。
- 在内容附近显示作者/整理者、来源、版本与必要的授权状态；不要只在页脚或二级弹窗中解释来源。
- 分享卡片/详情公开身份只限基础名称和头像；每条分享可选择匿名身份或用户自填昵称。匿名时使用通用匿名名称和头像，不透出 Profile 昵称/头像；手机号、邮箱等认证/找回资料不公开。MVP 提供约 10 个内置 Q 版《道德经》风格头像，注册后自动分配，之后可在 Profile 更换。
- 核心人物身份标记表达“身份/来源经核验”，不表达平台为观点背书。
- 分享、转录、摘要等派生内容应能回到原作者、活动或源媒体。

### 2.3 频道优先，轻量加入与持续参与

- 81 个章节频道是系统预置的长期内容空间，不由用户逐场创建。
- 用户可匿名浏览章节和公开内容；登录后可发布章节分享、爱心、评论和单章节共读记录。一次活动只提交一个章节；频道互动限于轻量评论，不扩展成论坛式话题社区。
- 章节分享与明确关联本章的站内公开内容是章节频道核心内容；可附原网页链接和来源。共读记录作为独立记录关联章节。
- 分享内容关联作者、提交时间和章节，可回链到对应章节；活动记录也关联其章节与地点。
- 清楚区分共读记录的服务端提交时间与内容创建/更新时间；提交时间自动生成并精确到分钟，不提供活动发生时间回填字段。
- MVP 每条分享关联一个章节；在当前章节频道内发布时自动关联当前章，不允许一条分享多章重复发布。
- 界面说明内容的公开状态、隐藏方式和更正/删除申请入口。
- 媒体上传是可选表达方式，不成为发布分享、发言或互动的阻塞条件。

### 2.4 隐私与公开状态可理解

- 在收集身份、精确地点、联系方式或媒体前说明这些信息将如何展示；内容及用户明确选择附上的现场媒体默认公开，发布者可在发布后手动隐藏。作者可逐条选择匿名或公开昵称。
- 提交前明确显示公开范围和可见对象，且把“隐藏”“撤回/删除申请”“更正”入口放在用户能找到的位置。
- 城市级发现与街道级到达信息分层呈现；提交临时地点时清楚提示其公开到街道级，并由本次活动中实际到场的发起人编辑/纠正并标记可到达地址。
- 媒介以文字和音频为优先，图片作为补充；不建议现场视频，发布界面不主动鼓励视频。上传可识别第三方声音/影像前提供授权/去标识提醒。
- 默认公开是已确认的产品原则。界面须明确展示公开字段和内容创建者/管理员可用的管理入口。

### 2.5 地点先理解再导航

- 道场资料、固定道场关联与临时地点记录在界面上使用清楚的状态和来源标记。
- 道场发现默认显示杭州地图，并提供地图/列表切换及省市筛选；地图和地址列表不获取设备定位。道场详情提供高德/百度地图外跳，不在 MVP 内显示产品自算路线或预计用时。
- 对临时地点说明地址的维护者、更新时间和可见精度；由活动中实际到场的发起人编辑或纠正。MVP 不提供地点归并界面。
- MVP 不提供附近距离排序。地点关联 POI 时才请求定位，不做后台持续追踪；拒绝定位或无有效 POI 时允许无地理信息继续。城市地图和省市列表可直接浏览。

### 2.7 编辑式版面，控制卡片密度

- 产品默认以内容和阅读节奏组织页面，不套用仪表盘式“每块内容一个卡片”的统一模板。
- 长文、经文、分享正文和评论用连续排版、标题层级、留白和细分隔线组织；避免每段文字都用边框、圆角、彩色底框封装。
- 卡片/面板用于真正独立的对象或操作：地图结果、地点条目、媒体预览、表单组、权限/成功/错误状态。使用时保持目的明确，不重复包裹嵌套内容。
- 读书页保持书页式正文；章节频道采用开放式内容条目；发现地图和资料/表单可继续使用清晰的功能容器。不同页面按任务选择版式，不强行全产品同构。
- 视觉层次通过字号、字重、行距、段落间距、缩进、编号和留白建立。重要操作易找到，但不以大色块按钮占据内容主视区。

### 2.6 渐进披露，避免首期功能越界

- 搜索、繁简转换、全文对照属于后续候选，首期布局为未来扩展留出位置，但不制造已上线的假象。
- AI 不作为首期主导航或关键任务依赖；未来生成内容应与经典原文、经核实注释和用户分享清晰区隔，并提供来源引用。
- 提交数、十万次目标和后台重复合并都不进入 MVP 页面；原始记录仅沉淀供未来审计。

## 3. 全局信息架构建议

建议首期全局一级导航保持精简，围绕主要任务组织：

| 一级区域 | 主要任务 | 内容范围 |
| --- | --- | --- |
| 读书 | 核心产品入口：阅读《道德经》并进入 81 个章节频道 | 1—81 章目录、章节原文/注释/解读、每章默认频道及关联内容 |
| 发现 | 线下到场道场发现 | 默认杭州地图；地图/列表切换；按省、市浏览固定道场和有有效 POI 的临时地点，区分地点类型 |
| 我的 | 管理本人资料与贡献 | 账号资料、我的分享/共读记录、道场维护入口及内容管理 |

移动端底部导航固定为以上三项：读书、发现、我的。默认落在“读书”，突出核心阅读任务。章节分享在对应章节频道内浏览；“发现”只提供道场地图与省市列表。频道内容发布从章节页或章节频道触达。MVP 不建设运营审核与资料维护工作区；账号注册后才能发布、提交记录或维护道场。

**频道层级（首期建议）**

- 81 个章节各自对应一个默认、长期存在的章节频道，是“读书”中的主骨架。
- 分享内容属于章节频道，不进入发现 Tab 的通用内容流；从章节阅读进入频道，再点分享卡片进入详情，详情可返回所属频道。
- MVP 每条分享只关联一个章节；章节频道聚合该章原文入口和站内公开分享，支持爱心与单层评论，不设话题论坛。
- 后续可增加运营主题频道；一期不扩展章节频道之外的频道类型作为一级入口。
- 活动记录是独立对象，可关联章节频道、分享和道场；不等同于频道，也不进入首期道场发现结果。
- 未来可另行评估跨章节内容信息流或活动推荐；不属于当前发现模块 MVP。

## 4. 响应式框架

断点以内容和交互是否需要并排为准，而非绑定某一设备型号。以下尺寸为原型起始值，需结合实际内容和可用性观察调整：

| 区间 | 布局策略 | 重点 |
| --- | --- | --- |
| 窄屏：≤ 767 px | 单列、移动优先；底部导航或轻量顶栏 | 单手可达、正文连续、频道内容流易浏览和参与、轻量输入、关键操作固定但不遮挡内容 |
| 中屏：768—1199 px | 单主列为主；可使用折叠侧栏或双列浏览 | 目录与正文按任务切换，减少拥挤并保留内容宽度 |
| 宽屏：≥ 1200 px | 主内容列加辅助导航/上下文栏 | 目录、正文、来源/关联内容可并列；管理工作区可用多栏 |

**自适应规则**

- 长文正文应设最大行宽，桌面端不横跨整个视口；窄屏保证舒适阅读字号和行距。
- 窄屏阅读原文采用适配屏幕的逐页横向翻阅；目录、注释内容及其他长列表可垂直滚动，避免正文出现二维滚动。
- 目录在桌面端可常驻侧栏或抽屉；移动端使用可快速打开的章节目录面板，并标出当前章。
- 关联分享与道场信息在小屏放到正文之后或折叠区；桌面端可放入侧栏，但不得挤压正文可读宽度。
- 工具栏、筛选和次级操作应随内容层级折叠；常用操作保持可发现，低频操作不占据首屏。

## 5. 关键页面布局指导

### 5.1 读书 Tab 与默认阅读入口

**首屏优先级**：继续阅读位置与章节索引 → 当前阅读进度与轻量阅读控制 → 章节频道入口。进入具体章节后转为沉浸式连续正文，不延续目录的工具化布局。移动端默认进入“读书”，不以推荐流作为产品首页。

- 移动端阅读页采用单列、连续的书籍式排版；桌面端可用章节侧栏加正文画布，但正文保持独立、稳定的阅读宽度。
- 阅读入口同时可见 81 章目录、继续阅读位置和进入章节频道的路径。
- 发现内容、活动和道场提供次级入口，避免干扰阅读主任务。
- 不把长期十万次目标或未经后台合并判定的计数放在首屏作为公益成果数字。

### 5.2 章节目录

目录按书籍目录/章节索引组织：章节号与章名形成连续列表，用留白和细线区分，不把每章包进有底色、有圆角的小卡片。继续阅读位置可用轻量标记突出，不另造推荐卡片。

- 81 章按序号稳定排列，章节号作为主要定位锚点；章名在来源版本存在时显示。
- 明确当前选中章节、最近阅读位置与目录返回关系。
- 桌面端支持侧栏目录或列表加阅读区；移动端使用全屏/抽屉式目录，选章后返回阅读上下文。
- 每一章除阅读入口外，都有对应的章节频道入口；目录项可区分“阅读本章”和“进入本章频道”，或在章节页内明确频道入口。
- 未来搜索可作为目录扩展，不应影响首期目录可扫描性。

### 5.3 章节阅读页

移动端的竞品依据、视觉变量、交互状态与可用性验证见 [移动端阅读体验 Spec](mobile-reading-experience-spec.md)。底部浮层提供收起、半屏、顶部三档，容纳本章注释和本章分享。

- 正文是分页书页画布，保留连续的阅读顺序；首屏以章节标题、版本/来源小字和原文为主，不堆叠卡片或指标。
- 以阅读字体、行距、段落留白和原文断句建立节奏。移动端正文行宽接近视口并留舒适边距；桌面端限制最大行宽，避免长行。具体字级与行宽作为原型变量验证。
- 本章注释半屏依次呈现「白话注释」和「河上公」。白话注释按原文逐句对应，以直白释义解释词义和句意；必要语境说明与释义分开，不写整章思想评论或人生建议。逐句对应、来源或审校状态不可靠时标明待补/待核。河上公展示经独立核验的古注原文，来源信息低调呈现，缺失层保留标题并提示待补。
- 阅读首屏轻量呈现目录、章节、注释及「本章分享」；左右滑逐页阅读，章节边界进入相邻章。字号等收进更多菜单；提供等价按钮，关键任务不能只依赖手势。
- 浮条可轮换当前章注释提示和按有效阅读数排序的分享；展开后按「注释 / 本章分享」切换，末页和分享区提供完整频道入口。浮层不设遮罩，半屏时未遮挡的原文仍可翻页；浮层高度只由把手手势调整。

- 顶部：目录、章号与更多；字号位于更多菜单。阅读专注模式隐藏全局 Tab，退出阅读后恢复。
- 正文：原文作为视觉主层级；注释、解读采用明确标题、编号或折叠层级，不混排成一段。
- 辅助：字号控制、阅读进度、版本/来源入口。
- 阅读浮层展示本章分享，章节末页提供分享摘要或空态及频道入口；不将个人分享包装为经义注释。
- 桌面端可固定目录导航和当前章上下文；移动端以左右翻页为主，并允许注释半屏独立滚动。

### 5.4 章节频道分享浏览

频道沿用编辑式阅读语言：分享作为连续内容条目呈现，用作者与时间小字、正文排版和细分隔线分组；仅媒体、引用或独立操作需要边界容器，避免每条分享都成为同款小卡片。评论也用轻量行文与分隔线，不堆叠容器。

- 章节频道是核心内容与轻社交场所，汇集明确关联当前章节的站内公开分享；外部网页以来源链接呈现，不抓取/复制全网内容。默认按有效阅读数排序，提供“最新”切换。
- 分享条目可包括体悟、金句、生活洞察和带来源的外链分享；显示作者、时间、内容类型、来源和章节。显示阅读量、爱心数和评论数；突出指标不替代内容来源。
- 点击内容条目进入分享详情；详情显示关联章节并可返回所属频道。
- 81 个章节频道长期存在；频道详情以章节作为主上下文，聚合原文入口和相关分享。
- 频道分享默认按有效阅读数降序；“最新”按发布时间倒序。只在当前章节内排序，不跨章推荐。阅读数不代表内容质量或经义权威度。
- 活动保持独立对象，可在章节频道或分享详情中作为关联信息出现；不在发现 Tab 建立活动/洞察信息流。
- 频道头部轻量展示章号/章名和原文入口；排序控件清楚区分“有效阅读数/最新”，不让阅读量或爱心数压过章节上下文。
- 分享与活动上下文在内容类型、来源和时间上可区分；用户贡献不与经典原文/经核实注释混排。

### 5.5 内容发布与频道互动

81 个章节频道由系统预置，不要求用户创建。频道内容以关联当前章的公开分享为中心；用户轻量发布并自动带入章节，可附外部来源链接。注册用户可爱心和发表评论，未登录用户只读浏览。

**轻量创建入口建议**

- 发布入口从章节页或章节频道触达；在章节频道内发布时默认关联当前章节。发现 Tab 不提供内容发布入口。
- 以一段文字/金句/生活体悟即可发布；章节关联必需，来源链接与媒体可选。共读记录另行一步提交，地点/道场和章节必需，提交时间由服务端自动记录。
- 发布后生成分享详情页，并回链至作者、来源和所属章节频道。
- 频道内的主操作是阅读分享、发布、爱心和单层评论；暂不实现评论回复、关注、私信或收藏。爱心和评论需登录；未登录操作时触发登录并回到原帖。
- 在发布输入附近说明公开范围、作者身份展示和隐藏/删除申请方式；媒体保持可选。
- 活动信息若作为内容附加，不要求组织者确认、参与者共同确认、签到或二维码。
- 发布成功后直接进入内容详情；提供返回所属章节频道的路径，而非只显示提交回执。

#### 后续：线下共修自愿录制（不属于 MVP）

线下流程包含静心、领读、“三生万物”三人自由交流、小组代表发言、生活故事分享、简短总结与合影；页面不应把这些步骤变成必须使用产品完成的任务。所有共读活动默认公开；由一位相关人员使用一台设备录制完整共读过程，开始时启动、结束时停止，不要求现场阶段切换或每位参与者操作手机。录音后再转写整理和校对，形成公开记录。详情见[线下共修流程与自愿记录概念 Spec](./offline-gathering-capture-concept-spec.md)。

活动及原始录音默认公开；AI 转写和整理稿先作为编辑草稿，校对后公开。录制、转写和整理是清楚分开的处理步骤。静心环节也属于整场录音范围，不另设阶段性排除。

**频道内容流布局**

- 移动端章节频道采用单列编辑式分享流，发布入口易触达；发现页以地图为默认视图，并提供地图/列表切换。
- 桌面端内容详情以正文/卡片为主栏，章节和作者/来源上下文可放辅助栏。
- 分享条目展示有效阅读数/最新排序状态、有效阅读量、爱心数、评论数；来源、作者、所属章节仍优先于互动指标。有效阅读数排序限于章节内，提供“最新”对照并对新内容留出发现机会。
- 章节频道空状态引导阅读本章或发布第一条分享。
- 评论按时间顺序展示并沉淀作者、章节、互动时间等结构化数据，供未来评估活跃讨论；作者可删除自己的评论。分享作者可隐藏/逻辑删除本人帖子并连带从公开频道撤下。具备基础限流和作者自删。

### 5.6 道场地图、列表与详情

- 道场发现默认地图模式；首期默认呈现杭州、浙江区域，地图与列表可切换并使用相同结果集。
- 移动端地图下方提供可收起的列表面板，也允许切换到完整列表；桌面端地图与列表并排。
- 地图标记与列表项双向联动：点标记高亮对应列表项，点列表项将地图移至对应道场；地图缩小时对重叠标记聚合。
- 杭州一期以目前掌握的约 20 个道场为首批资料覆盖目标，不是产品容量上限；需核实名称、行政区、公开地址、坐标、活动方式、联系方式和资料更新时间。
- 道场列表项展示名称、行政区/片区、活动方式、简短介绍和最近更新时间；详情页展示公开地址及联系方式。
- 地图与省市列表按城市浏览不申请定位；定位授权仅用于匹配有效 POI，不做附近排序或后台追踪；拒绝定位或没有有效 POI 时可无地点继续提交。
- 详情页突出名称、介绍、活动方式、公开联系方式、维护者/更新时间和关联活动。
- 道场详情需直接回答新人“去哪里、何时去、是否欢迎初次参与者、如何联系”：展示常规共读时间规则、新人欢迎状态、公开联系方式选择和已有的外部报名渠道说明/链接。站内报名不属于 MVP-1，列入 MVP-2。
- 导航区提供高德地图、百度地图跳转；MVP 不提供产品内路线规划和预计用时。
- 临时地点需标注“临时/未收录”及地址来源/维护状态；街道级到达地址的公开范围必须与授权及治理口径一致。

### 5.7 个人资料与内容管理

- 允许用户查看其提交的共读记录与分享，并可隐藏或逻辑删除自己的分享。
- 隐藏后立即停止公开访问；逻辑删除不再对外返回，保留必要 tombstone/关联。
- 身份资料与公开展示字段分开设置，避免自助填写的身份被误当成平台核验身份。
- 分享发布时可选择“匿名分享”或“使用公开昵称”；匿名仅表示对其他用户隐藏 Profile 昵称，账号在后台仍与内容关联以支持删除、治理和作者本人管理。注册/发布告知不得承诺对平台匿名。
- 注册不要求用户选择头像；初始从内置头像中自动分配，之后可在 Profile 中更换。
- 手机号注册时无需提供邮箱；用户可在个人资料设置中选填并验证找回邮箱。

## 6. 跨端交互和可访问性基线

- 触控目标适合手指操作，关键路径无需精细点击；键盘用户能完成目录、表单、筛选和弹窗操作。
- 状态不仅依靠颜色表达；焦点、选中、错误、公开/隐藏等状态同时使用文字或图标说明。
- 表单字段有清晰标签、必填/选填说明、即时错误提示和保留用户输入的能力。
- 页面标题、章节序号、内容类型标记保持一致，利于屏幕阅读器理解结构。
- 外部地图跳转、上传中、审核/申请处理中等异步状态均有明确反馈。
- 长文适配浏览器缩放；字号调整不破坏目录、引用和导航操作。

## 7. 设计边界与暂不承诺

- 本文定义布局指导原则，不代表高保真视觉方案、品牌规范或最终交互稿。
- 首期不假设实现复杂地图导航、实时定位、签到管理、活动真实性自动审核、重复记录自动合并或面向公众的权威统计。
- AI 功能属于后续候选；如进入界面，需先具备权限控制、来源链接、生成内容标签和人工反馈路径；当前不接入外部 AI 数据源。
- 版本底本、注释作者及媒体授权说明仍待产品/内容负责人确认。账号统一注册登录，不做手动身份录入和认领。

## 8. 批判性审视：已确认原则及仍待收敛点

### 8.1 线框评审验收问题

1. 访客能否从读书入口找到章节，并进入该章分享？
2. 注册流程是否足够轻；分享公开身份仅为基础名称和头像？
3. 临时地点定位是否在用户发起相关操作时请求授权，能否核对系统解析出的地址？
4. 道场地图和省市列表能否告诉新人“去哪里、何时去、如何联系”？
5. 分享人是否理解隐藏和逻辑删除的区别；页面不出现提交数或十万次成果数字？

每个核心分镜须至少能回答上述相关问题；没有覆盖到的项目标记为待验证，不用装饰完整度代替任务验证。

以下原则已确定；设计需要将其落实到交互和提示中：

1. **默认公开的后果如何让用户真正理解？** 公开身份、现场媒体及街道级地点已是产品原则；需用明确的提交前告知、发布后隐藏入口和第三方素材投诉流程落实，避免原则在界面上被误读为隐私选项。
2. **地点纠错如何防止误改？** 临时地点由实际到场的活动发起人编辑/纠正，MVP 不做地点归并。界面需显示维护者与更新时间；由创建者或管理员直接管理内容。
3. **身份如何关联内容和贡献？** 用户须先注册并登录，产品资料及贡献归属登录账号；没有预录入用户或手动认领流程。核心讲授者等身份标记仍由本人或授权管理员核验。
4. **定位授权如何说明？** 首期道场地图和省市列表不需要设备定位，也不提供附近排序；只有关联有效 POI 时才请求定位，不做持续追踪。拒绝授权或无有效 POI 时仍可提交章节内容。
5. **未来推荐依据如何解释和纠偏？** 个性化推荐不属于 MVP；未来若加入，应区分编辑精选、近期内容和个性化排序，并提供可理解的排序来源与反馈方式。
6. **轻互动边界如何控制？** MVP 支持章节内爱心和单层评论，其他回应、评论回复、关注或私信留待治理与运营能力验证后再定。

默认公开、POI 可选关联、身份归属及 MVP 提供章节内轻量互动和有效阅读数排序，但无跨章节推荐算法。有效阅读埋点口径、评论治理细则和 AI 使用边界按本节后续事项管理。

| Meetup 活动/群组 | 群组信息与具体活动分开展示；群组页提供 About、Events、Members、Photos、Discussions 等分区，活动有 List/Calendar 两种视图。[Meetup 群组页面示例](https://www.meetup.com/support-meetup-group/) | 活动与讨论分区组织；列表/日历是不同活动浏览方式；照片可作为可选回顾素材。章节频道或道场详情可借鉴清楚的子区结构。 | 本项目首期活动是已发生记录，不是待报名的未来活动；不能照搬 RSVP、签到、成员名册或未来活动日历而不扩展范围。 |

**复审后的设计调整建议**

1. **首期发现只解决到场道场查找。** 默认杭州地图，可切换列表并按省市浏览；地图标记和列表条目包含固定道场与有有效 POI 的临时地点，并清晰标注类型；临时地点不自动转为固定道场。分享内容在所属章节频道中发现，不在发现 Tab 混入推荐流。后续如新增跨章节推荐，再分别设计推荐与主动探索任务。
2. **建立分享内容到源头的闭环。** 章节频道分享卡片 → 内容详情 → 所属章节频道 → 原文/相关分享；如内容关联活动，再由详情进入独立活动页。每一步都显示作者、内容类型、章节和来源，不让体悟卡片脱离经典上下文。
3. **把频道作为目录型社区而非用户自建群组。** 81 个章节频道由系统预置；首期发现不承载运营专题筛选或内容精选，未来专题需要持续成员关系和独立治理时再评估是否升级为频道。
4. **冷启动时不伪造个性化。** 未来如建设跨章节内容推荐，新用户或低信号用户先看到编辑精选、近期内容与明确的章节推荐；有足够使用信号且用户知情后，再逐步增加个性化排序。
5. **避免用活跃度冒充内容质量。** 有效阅读数作为频道分享排序的最高优先级；先发优势和异常流量可能扭曲结果，需定义去重和异常流量规则，并提供“最新”视图。
6. **为弱参与用户保留只读路径。** 用户可匿名浏览原文和公开分享；发布、爱心和评论需登录，但登录提示应回跳原帖/原操作。
7. **保持频道为轻量阅读与分享空间。** MVP 支持章节内有效阅读数/最新排序、阅读量、爱心和单层评论；不扩展话题、评论回复、关注或私信。评论开放前需具备基础限流和本人删除。
8. **借鉴 Meetup 的信息分区和活动状态，但按本项目实体重组。** 参考其 Events、Calendar、Discussions 分区，以及活动照片/回顾的组织方式。道场详情未来可分为“介绍、活动、讨论/分享、照片”，章节频道保持章节内容与分享为主、关联活动为独立入口。首期频道提供单层评论区，但不建设话题讨论版或楼中楼；移动端用清晰评论列表/输入区，桌面端可用正文与评论并列。首期也不需要成员名册或加入群组关系。
9. **列表/日历和状态需准确表达活动生命周期。** 首期 `Gathering` 是已发生的共读记录，没有 RSVP 或活动状态切换；可按日期浏览，但不得暗示未来报名。只有新增 `PlannedEvent` 并定义计划中、报名开放、已满、已取消、已结束等状态后，才提供 Meetup 式 List/Calendar 切换与状态标识。活动照片/回顾是可选素材，不改变活动实体状态。
10. **媒体/照片区保持可选并尊重公开规则。** 可在活动/道场详情提供照片或媒体回顾区，但必须与分享条目来源、作者、授权和隐藏状态关联；空状态和无媒体活动均应正常呈现。

结合“阅读是核心入口”的产品优先级，一级导航调整为三个 Tab（读书、发现、我的）；“发现”首期承接道场地图/省市列表，不承接原首页内容推荐流。81 章频道骨架不变，分享浏览留在对应章节频道。Meetup 的 Events/Calendar/Discussions 与活动状态只作为后续活动体验的结构参考，不代表首期上线未来活动、报名或频道讨论功能。竞品观察只提供模式证据，不能替代本项目用户试点验证。

## 9. 可验证的设计验收标准

以下为原型/可用性检查的建议标准，数值是起始目标，不是当前已测结果：

| 检查项 | 验收描述 | 建议测量方式 / 起始目标 |
| --- | --- | --- |
| 找到指定章节 | 新用户能从入口进入指定章并识别当前章节 | 移动端任务成功率 ≥ 90%；记录完成时间与错误跳转 |
| 区分内容类型 | 用户能区分原文、注释、平台说明与个人分享 | 测试后正确分类率 ≥ 90% |
| 章节阅读 | 用户能左右翻页、上滑或点击查看注释、进入本章分享并回到原文 | 观察任务成功率 ≥ 90%，记录手势误触和入口发现情况 |
| 找到章节频道 | 用户能从“读书”进入指定章节频道并理解其内容归属 | ≥ 90% 受试者无协助完成；记录完成时间与误入路径 |
| 理解频道排序与互动 | 用户能区分“有效阅读数/最新”，理解阅读量、爱心与评论的作用；能完成一条评论 | 任务成功率 ≥ 85%；记录误解为权威质量排序的比例 |
| 发布与互动 | 用户能在章节频道发布分享、爱心并发表评论，理解可见范围和所属章节 | ≥ 90% 受试者无协助完成；首条文字内容中位发布时间 ≤ 2 分钟 |
| 理解发现卡片去向 | 用户知道章节频道卡片打开分享详情，并能返回所属章节频道 | 测试后正确理解率 ≥ 90% |
| 区分读书与发现 | 用户能说明“读书”与“发现”的不同任务，并完成对应任务 | 任务分类正确率 ≥ 85%；记录误用导航的情况 |
| 理解公开范围 | 提交前能说出哪些字段会公开，以及如何隐藏/申请删除 | 理解正确率 100% 作为发布交互的放行门槛 |
| 找到道场 | 用户可在地图/列表间切换，并按省市找到目标固定道场及地址；无需位置授权 | 任务成功率 ≥ 85% |
| 发现授权状态 | 用户能找到分享者、来源和必要授权/可见状态 | 关键来源字段可发现率 100% |

测量时按移动端优先，并覆盖至少一种桌面宽屏；样本和试点环境应记录。若目标未达到，优先修订信息层级、字段说明与导航路径，而不是增加说明文字堆叠。

## 10. 后续体验与运营细节（不阻塞 MVP 编码）

- 如何在提交前清楚告知默认公开范围，以及第三方媒体的公开范围和管理入口。
- 如何呈现临时地点的编辑者、更新时间、编辑入口。
- 注册登录后产品资料、核心人物核验标记与用户贡献之间的展示关系。
- 发现中“活跃/精选/与我有关”推荐流的默认呈现与试点评价方式。
- 首期已发生活动记录如何关联章节分享/道场；日期浏览只针对已提交记录，活动推荐、未来活动和报名不在 MVP。
- 后续是否借鉴 Meetup 的详情子区结构，以及照片/媒体回顾、活动状态和成员关系的范围。
- 有效阅读按同一访客和分享的 Asia/Shanghai 自然日去重；触发条件、访客键、异常行为规则及并列排序次序须在实现前定义。
- 评论限流阈值和适用社区规则；MVP-1 提供基础限流和本人删除。
- 评论/分享数据用于 AI 或数据挖掘的独立授权、脱敏、删除传播和评估方案。
- 后续内容推荐的信号、精选/热度区分、用户反馈与默认排序策略。
- 设计验收指标的样本、设备范围与是否采用本 Spec 的起始目标。

> 本文是供讨论与原型设计使用的指导 Spec。MVP 核心范围已确定；以上条目用于后续体验与运营细化，不阻塞编码计划。页面交互应与数据字段、公开范围和内容治理边界保持一致。
