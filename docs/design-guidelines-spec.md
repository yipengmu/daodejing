# 《道德经》公益在线共读平台：PC 与移动端布局设计指导原则

- 状态：讨论稿 v0.1
- 日期：2026-10-31
- 依据：[`docs/proposal-spec.md`](./proposal-spec.md)
- 适用范围：响应式 Web 产品的首期信息架构与布局框架；不定义视觉品牌、最终文案或高保真组件样式
- 设计目标：以移动端为优先，同时让桌面端适合长文阅读、内容发现与资料管理

## 1. 设计任务与产品重心

首期产品围绕三个相连但边界清晰的任务组织，定位偏内容并带有适度社交属性：

1. **读经典与章节频道**：快速找到 1—81 章，连续阅读原文、注释与解读，并进入对应章节频道浏览和贡献内容。
2. **发现到场道场**：打开地图或按省、市查看已收录道场地址。首期“发现”Tab 不承载洞察内容流、跨章节分享发现或推荐。
3. **管理个人贡献**：查看本人资料与分享/记录，隐藏或逻辑删除本人分享。

章节频道是持续承载章节分享的长期空间；活动记录是独立对象。活动记录不是签到、到场证明或活动审批。布局与交互不得让用户误以为必须预登记、签到、上传媒体或等待组织者确认，才能发布或提交记录。

## 2. 设计原则

### 2.1 阅读优先，降低进入成本

- 全局首要入口是“读书”；阅读是首期最稳定、最常用的核心路径。“发现”首期聚焦道场地图/省市列表，不设置独立首页推荐流。
- 目录按第 1—81 章顺序呈现，提供明确的当前阅读位置和快速跳章方式。
- 章节页优先呈现原文；注释、解读与共修分享在视觉层级和内容标签上明确区分。
- 阅读过程中提供上一章、下一章、回目录、字号调整与进度记忆入口；章节频道入口清楚可见但不打断正文。

### 2.2 内容来源与身份清楚可见

- 原文、注释、平台编辑说明、用户分享和 AI 派生内容使用不同的内容类型标识。
- 在内容附近显示作者/整理者、来源、版本与必要的授权状态；不要只在页脚或二级弹窗中解释来源。
- 核心人物身份标记表达“身份/来源经核验”，不表达平台为观点背书。
- 分享、转录、摘要等派生内容应能回到原作者、活动或源媒体。

### 2.3 频道优先，轻量加入与持续参与

- 81 个章节频道是系统预置的长期内容空间，不由用户逐场创建。
- 用户可匿名浏览章节和公开内容；登录后可发布章节分享和逐章共读记录。MVP 不提供话题、评论等频道互动。
- 章节分享是章节频道首期内容；共读记录作为独立记录关联章节。
- 分享内容关联作者、提交时间和章节，可回链到对应章节；活动记录也关联其章节与地点。
- 清楚区分共读记录的服务端提交时间与内容创建/更新时间；提交时间自动生成并精确到分钟，不提供活动发生时间回填字段。
- 内容可关联一个或多个章节频道；在当前章节频道内发布时默认关联当前章，不能让用户误以为每章都需重复发布。
- 界面说明内容的公开状态、隐藏方式和更正/删除申请入口。
- 媒体上传是可选表达方式，不成为发布分享、发言或互动的阻塞条件。

### 2.4 隐私与公开状态可理解

- 在收集身份、精确地点、联系方式或媒体前说明这些信息将如何展示；身份信息、现场媒体与已提交内容默认公开，发布者可在发布后手动隐藏。
- 提交前明确显示公开范围和可见对象，且把“隐藏”“撤回/删除申请”“更正”入口放在用户能找到的位置。
- 城市级发现与街道级到达信息分层呈现；提交临时地点时清楚提示其公开到街道级，并由本次活动中实际到场的发起人编辑/纠正并标记可到达地址。
- 上传含可识别第三方的图片、音频或视频时，提供授权/去标识提醒。
- 默认公开是已确认的产品原则。界面仍须明确展示公开字段、隐藏入口及第三方媒体的举报/纠错处理方式；不能用隐私提示暗示用户已选择私密。

### 2.5 地点先理解再导航

- 道场资料、固定道场关联与临时地点记录在界面上使用清楚的状态和来源标记。
- 道场发现默认显示杭州地图，并提供地图/列表切换及省市筛选；地图和地址列表不获取设备定位。道场详情提供高德/百度地图外跳，不在 MVP 内显示产品自算路线或预计用时。
- 对临时地点说明地址的维护者、更新时间和可见精度；由活动中实际到场的发起人编辑或纠正。MVP 不提供地点归并界面。
- MVP 不提供附近距离排序。临时地点录入依赖用户主动授权的前台定位，不做后台持续追踪；城市地图和省市列表可直接浏览。

### 2.6 渐进披露，避免首期功能越界

- 搜索、繁简转换、全文对照属于后续候选，首期布局为未来扩展留出位置，但不制造已上线的假象。
- AI 不作为首期主导航或关键任务依赖；未来生成内容应与经典原文、经核实注释和用户分享清晰区隔，并提供来源引用。
- 次数统计与后台重复合并不是首期主要用户任务；不以醒目的总数驱动首屏，也不把原始提交数呈现为独立活动数。

## 3. 全局信息架构建议

建议首期全局一级导航保持精简，围绕主要任务组织：

| 一级区域 | 主要任务 | 内容范围 |
| --- | --- | --- |
| 读书 | 核心产品入口：阅读《道德经》并进入 81 个章节频道 | 1—81 章目录、章节原文/注释/解读、每章默认频道及关联内容 |
| 发现 | 线下到场道场发现 | 默认杭州地图；地图/列表切换；按省、市浏览已收录固定道场并查看公开地址 |
| 我的 | 管理本人资料与贡献 | 账号资料、我的分享/共读记录、道场维护入口及内容管理 |

移动端底部导航固定为以上三项：读书、发现、我的。默认落在“读书”，突出核心阅读任务。章节分享在对应章节频道内浏览；“发现”只提供道场地图与省市列表。频道内容发布从章节页或章节频道触达。MVP 不建设运营审核与资料维护工作区；账号注册后才能发布、提交记录或维护道场。

**频道层级（首期建议）**

- 81 个章节各自对应一个默认、长期存在的章节频道，是“读书”中的主骨架。
- 分享内容属于章节频道，不进入发现 Tab 的通用内容流；从章节阅读进入频道，再点分享卡片进入详情，详情可返回所属频道。
- 内容可关联一个或多个章节频道；章节频道聚合该章原文和分享体悟、金句、生活洞察等章节分享，不含首期评论/话题。
- 后续可增加运营主题频道；一期不扩展章节频道之外的频道类型作为一级入口。
- 活动记录是独立对象，可关联章节频道、分享和道场；不等同于频道，也不进入首期道场发现结果。
- 未来可另行评估跨章节内容信息流或活动推荐；不属于当前发现模块 MVP。

## 4. 响应式框架

断点以内容和交互是否需要并排为准，而非绑定某一设备型号。以下尺寸为原型起始值，需结合实际内容和可用性观察调整：

| 区间 | 布局策略 | 重点 |
| --- | --- | --- |
| 窄屏：≤ 767 px | 单列、移动优先；底部导航或轻量顶栏 | 单手可达、正文连续、频道内容流易浏览和参与、轻量输入、关键操作固定但不遮挡内容 |
| 中屏：768—1199 px | 单主列为主；可使用折叠侧栏或双列浏览 | 目录与正文按任务切换，减少拥挤并保留内容宽度 |
| 宽屏：≥ 1200 px | 主内容列加辅助导航/上下文栏 | 目录、正文、来源/关联内容可并列；管理工作区可用多栏 |

**自适应规则**

- 长文正文应设最大行宽，桌面端不横跨整个视口；窄屏保证舒适阅读字号和行距。
- 窄屏优先垂直滚动，不把核心正文放入横向滚动容器。
- 目录在桌面端可常驻侧栏或抽屉；移动端使用可快速打开的章节目录面板，并标出当前章。
- 关联分享与道场信息在小屏放到正文之后或折叠区；桌面端可放入侧栏，但不得挤压正文可读宽度。
- 工具栏、筛选和次级操作应随内容层级折叠；常用操作保持可发现，低频操作不占据首屏。

## 5. 关键页面布局指导

### 5.1 读书 Tab 与默认阅读入口

**首屏优先级**：继续阅读/章节目录 → 当前阅读进度与轻量阅读控制 → 章节频道入口。移动端默认进入“读书”，不以推荐流作为产品首页。

- 移动端以便捷目录和连续阅读为主；桌面端可使用章节侧栏加正文主栏。
- 阅读入口同时可见 81 章目录、继续阅读位置和进入章节频道的路径。
- 发现内容、活动和道场提供次级入口，避免干扰阅读主任务。
- 不把长期十万次目标或未经后台合并判定的计数放在首屏作为公益成果数字。

### 5.2 章节目录

- 81 章按序号稳定排列，章节号作为主要定位锚点；章名在来源版本存在时显示。
- 明确当前选中章节、最近阅读位置与目录返回关系。
- 桌面端支持侧栏目录或列表加阅读区；移动端使用全屏/抽屉式目录，选章后返回阅读上下文。
- 每一章除阅读入口外，都有对应的章节频道入口；目录项可区分“阅读本章”和“进入本章频道”，或在章节页内明确频道入口。
- 未来搜索可作为目录扩展，不应影响首期目录可扫描性。

### 5.3 章节阅读页

- 顶部：返回目录、章号/章名、上一章/下一章；窄屏控制高度，避免正文被挤到首屏以下。
- 正文：原文作为视觉主层级；注释、解读采用明确标题、编号或折叠层级，不混排成一段。
- 辅助：字号控制、阅读进度、版本/来源入口。
- 下方或独立入口：进入本章频道，浏览该章关联分享、体悟卡片、金句和生活洞察；不将个人分享包装为经义注释。
- 桌面端可固定目录导航和当前章上下文；移动端优先保障连续滚动和章节跳转。

### 5.4 章节频道分享浏览

- 章节频道是首期发现他人分享的主要入口；频道内按提交时间倒序展示公开分享。
- 分享卡片可包括体悟、金句、生活洞察等；显示作者、提交时间、内容类型、来源和当前章节关联。
- 点击卡片进入分享详情；详情显示关联章节并可返回所属频道。
- 81 个章节频道长期存在；频道详情以章节作为主上下文，聚合原文入口和相关分享。
- 频道内内容按提交时间倒序呈现；不使用互动热度或运营精选排序。
- 活动保持独立对象，可在章节频道或分享详情中作为关联信息出现；不在发现 Tab 建立活动/洞察信息流。
- 频道头部轻量展示章号/章名、原文入口、内容数或最近更新等有明确口径的信息；避免空泛的活动管理字段主导页面。
- 分享与活动上下文在内容类型、来源和时间上可区分；用户贡献不与经典原文/经核实注释混排。

### 5.5 内容发布与频道互动

首期章节频道由系统预置 81 个，不要求用户创建章节频道。用户以轻量内容发布进入贡献流程，关联章节可作为发布时选择项，也可从章节频道内发布时自动带入。

**轻量创建入口建议**

- 发布入口从章节页或章节频道触达；在章节频道内发布时默认关联当前章节。发现 Tab 不提供内容发布入口。
- 以一段文字/金句/生活体悟即可发布；章节关联必需，媒体可选。共读记录另行一步提交，地点/道场和章节必需，提交时间由服务端自动记录。
- 发布后生成可分享的内容详情卡片，并回链至作者、来源和所属章节频道。
- 频道内的主操作是阅读与发布章节分享；MVP 不实现评论、回应或收藏。
- 在发布输入附近说明公开范围、作者身份展示和隐藏/删除申请方式；媒体保持可选。
- 活动信息若作为内容附加，不要求组织者确认、参与者共同确认、签到或二维码。
- 发布成功后直接进入内容详情；提供返回所属章节频道的路径，而非只显示提交回执。

**频道内容流布局**

- 移动端章节频道采用单列分享流，发布入口易触达；发现页以地图为默认视图，并提供地图/列表切换，不默认固定占用屏幕的大型编辑器。
- 桌面端内容详情以正文/卡片为主栏，章节和作者/来源上下文可放辅助栏。
- 分享使用清楚的内容类型标签；来源、作者和提交时间优先于互动指标。
- 章节频道空状态引导阅读本章或发布第一条分享。
- MVP 不提供精选、置顶、评论管理等运营动作；隐藏与删除由作者管理本人内容。

### 5.6 道场地图、列表与详情

- 道场发现默认地图模式；首期默认呈现杭州、浙江区域，地图与列表可切换并使用相同结果集。
- 移动端地图下方提供可收起的列表面板，也允许切换到完整列表；桌面端地图与列表并排。
- 地图标记与列表项双向联动：点标记高亮对应列表项，点列表项将地图移至对应道场；地图缩小时对重叠标记聚合。
- 杭州一期以目前掌握的约 20 个道场为首批资料覆盖目标，不是产品容量上限；需核实名称、行政区、公开地址、坐标、活动方式、联系方式和资料更新时间。
- 道场列表项展示名称、行政区/片区、活动方式、简短介绍和最近更新时间；详情页展示公开地址及联系方式。
- 地图与省市列表按城市浏览不申请定位；临时地点提交的定位授权只用于该活动流程，不做附近排序或后台追踪。
- 详情页突出名称、介绍、活动方式、公开联系方式、维护者/更新时间和关联活动。
- 导航区提供高德地图、百度地图跳转；MVP 不提供产品内路线规划和预计用时。
- 临时地点需标注“临时/未收录”及地址来源/维护状态；街道级到达地址的公开范围必须与授权及治理口径一致。

### 5.7 个人资料与内容管理

- 允许用户查看其提交的共读记录与分享，并可隐藏或逻辑删除自己的分享。
- 隐藏后立即停止公开访问；逻辑删除不再对外返回，保留必要 tombstone/关联。
- 身份资料与公开展示字段分开设置，避免自助填写的身份被误当成平台核验身份。
- 手机号注册时无需提供邮箱；用户可在个人资料设置中选填并验证找回邮箱。

## 6. 跨端交互和可访问性基线

- 触控目标适合手指操作，关键路径无需精细点击；键盘用户能完成目录、表单、筛选和弹窗操作。
- 状态不仅依靠颜色表达；焦点、选中、错误、公开/隐藏等状态同时使用文字或图标说明。
- 表单字段有清晰标签、必填/选填说明、即时错误提示和保留用户输入的能力。
- 页面标题、章节序号、内容类型标记保持一致，利于屏幕阅读器理解结构。
- 外部地图跳转、上传中、审核/申请处理中等异步状态均有明确反馈。
- 长文适配浏览器缩放；字号调整不破坏目录、引用和导航操作。

## 7. 设计边界与暂不承诺

- 本文定义布局指导原则，不代表高保真视觉方案、品牌规范或最终交互稿。
- 首期不假设实现复杂地图导航、实时定位、签到管理、活动真实性自动审核、重复记录自动合并或面向公众的权威统计。
- AI 功能属于后续候选；如进入界面，需先具备权限控制、来源链接、生成内容标签和人工反馈路径；当前不接入外部 AI 数据源。
- 版本底本、注释作者及媒体授权说明仍待产品/内容负责人确认。账号统一注册登录，不做手动身份录入和认领。

## 8. 批判性审视：已确认原则及仍待收敛点

以下原则已确定；设计需要将其落实到交互和提示中：

1. **默认公开的后果如何让用户真正理解？** 公开身份、现场媒体及街道级地点已是产品原则；需用明确的提交前告知、发布后隐藏入口和第三方素材投诉流程落实，避免原则在界面上被误读为隐私选项。
2. **地点纠错如何防止误改？** 临时地点由实际到场的活动发起人编辑/纠正，MVP 不做地点归并。界面需显示维护者与更新时间；举报/纠错渠道仍可用于处理争议。
3. **身份如何关联内容和贡献？** 用户须先注册并登录，产品资料及贡献归属登录账号；没有预录入用户或手动认领流程。核心讲授者等身份标记仍由本人或授权管理员核验。
4. **定位授权如何说明？** 首期道场地图和省市列表不需要设备定位，也不提供附近排序；只有提交临时地点时才需一次前台定位授权，不做持续追踪。拒绝授权时可改选已收录固定道场。
5. **未来推荐依据如何解释和纠偏？** 个性化推荐不属于 MVP；未来若加入，应区分编辑精选、近期内容和个性化排序，并提供可理解的排序来源与反馈方式。
6. **未来社区互动做到哪一步？** MVP 只有章节分享与共读记录；评论、回应、点赞、关注或私信留待社区治理与运营能力验证后再定。

默认公开、定位授权、身份归属及 MVP 无互动/无推荐算法均已确认。推荐与互动问题属于后续阶段，不阻塞 MVP 设计或编码计划。

### 8.1 竞品模式复审与对本项目的启发

本节不是完整的竞品功能清单，而是用相邻产品验证信息架构和内容关系。参考资料截至 2026-10-31；功能可能随产品版本调整。

**复审后的设计调整建议**

1. **首期发现只解决到场道场查找。** 默认杭州地图，可切换列表并按省市浏览；地图标记和列表条目指向同一固定道场资料。分享内容在所属章节频道中发现，不在发现 Tab 混入推荐流。后续如新增跨章节推荐，再分别设计推荐与主动探索任务。
2. **建立分享内容到源头的闭环。** 章节频道分享卡片 → 内容详情 → 所属章节频道 → 原文/相关分享；如内容关联活动，再由详情进入独立活动页。每一步都显示作者、内容类型、章节和来源，不让体悟卡片脱离经典上下文。
3. **把频道作为目录型社区而非用户自建群组。** 81 个章节频道由系统预置；首期发现不承载运营专题筛选或内容精选，未来专题需要持续成员关系和独立治理时再评估是否升级为频道。
4. **冷启动时不伪造个性化。** 未来如建设跨章节内容推荐，新用户或低信号用户先看到编辑精选、近期内容与明确的章节推荐；有足够使用信号且用户知情后，再逐步增加个性化排序。
5. **避免用点赞/评论数定义“比较好”。** “精选”应与互动热度分开标识；精选需有来源、责任人或规则，互动热度需考虑内容时效、异常行为和争议放大风险。
6. **为弱参与用户保留只读路径。** 用户可浏览原文和公开分享，不必先注册、关注、加入或发帖；发布、回应和个人化推荐按阶段引导。
7. **保持首期频道为轻量阅读与分享空间。** MVP 支持浏览和发布章节分享，不实现话题、评论、回应或收藏；后续是否扩展互动，应先验证社区治理与运营能力。
8. **借鉴 Meetup 的信息分区和活动状态，但按本项目实体重组。** 参考其 Events、Calendar、Discussions 分区，以及活动照片/回顾的组织方式。道场详情未来可分为“介绍、活动、讨论/分享、照片”，章节频道保持章节内容与分享为主、关联活动为独立入口。首期频道不实现评论/讨论区；移动端用清晰子页或分段切换，桌面端可用页内导航。首期也不需要成员名册或加入群组关系。
9. **列表/日历和状态需准确表达活动生命周期。** 首期 `Gathering` 是已发生的共读记录，没有 RSVP 或活动状态切换；可按日期浏览，但不得暗示未来报名。只有新增 `PlannedEvent` 并定义计划中、报名开放、已满、已取消、已结束等状态后，才提供 Meetup 式 List/Calendar 切换与状态标识。活动照片/回顾是可选素材，不改变活动实体状态。
10. **媒体/照片区保持可选并尊重公开规则。** 可在活动/道场详情提供照片或媒体回顾区，但必须与分享条目来源、作者、授权和隐藏状态关联；空状态和无媒体活动均应正常呈现。

结合“阅读是核心入口”的产品优先级，一级导航调整为三个 Tab（读书、发现、我的）；“发现”首期承接道场地图/省市列表，不承接原首页内容推荐流。81 章频道骨架不变，分享浏览留在对应章节频道。Meetup 的 Events/Calendar/Discussions 与活动状态只作为后续活动体验的结构参考，不代表首期上线未来活动、报名或频道讨论功能。竞品观察只提供模式证据，不能替代本项目用户试点验证。

## 9. 可验证的设计验收标准

以下为原型/可用性检查的建议标准，数值是起始目标，不是当前已测结果：

| 检查项 | 验收描述 | 建议测量方式 / 起始目标 |
| --- | --- | --- |
| 找到指定章节 | 新用户能从入口进入指定章并识别当前章节 | 移动端任务成功率 ≥ 90%；记录完成时间与错误跳转 |
| 区分内容类型 | 用户能区分原文、注释、平台说明与个人分享 | 测试后正确分类率 ≥ 90% |
| 连续阅读 | 用户能调整字号、找到上一章/下一章并继续阅读 | 观察任务成功率 ≥ 90%，记录操作中断点 |
| 找到章节频道 | 用户能从“读书”进入指定章节频道并理解其内容归属 | ≥ 90% 受试者无协助完成；记录完成时间与误入路径 |
| 发布内容 | 用户能从读书页或章节频道轻量发布分享，并理解可见范围和所属频道 | ≥ 90% 受试者无协助完成；首条文字内容中位发布时间 ≤ 2 分钟 |
| 理解发现卡片去向 | 用户知道章节频道卡片打开分享详情，并能返回所属章节频道 | 测试后正确理解率 ≥ 90% |
| 区分读书与发现 | 用户能说明“读书”与“发现”的不同任务，并完成对应任务 | 任务分类正确率 ≥ 85%；记录误用导航的情况 |
| 理解公开范围 | 提交前能说出哪些字段会公开，以及如何隐藏/申请删除 | 理解正确率 100% 作为发布交互的放行门槛 |
| 找到道场 | 用户可在地图/列表间切换，并按省市找到目标固定道场及地址；无需位置授权 | 任务成功率 ≥ 85% |
| 发现授权状态 | 用户能找到分享者、来源和必要授权/可见状态 | 关键来源字段可发现率 100% |

测量时按移动端优先，并覆盖至少一种桌面宽屏；样本和试点环境应记录。若目标未达到，优先修订信息层级、字段说明与导航路径，而不是增加说明文字堆叠。
